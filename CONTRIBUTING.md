# Работа над DocCheck

Базовая ветка — `main`. Начальный каркас опубликован одним коммитом; дальнейшая работа выполняется через отдельные ветки и pull request.

## Рабочая директория и ветка

Перед началом прочитать README, задачу Linear, её критерии, зависимости и относящиеся к ней документы. Агенты также следуют `AGENTS.md`. Объём работы и приёмка определяются задачей и указаниями владельца направления. Ветка называется `nrt-<номер>-<краткая-тема>`. По умолчанию для каждого активного агента создаются отдельная ветка и папка worktree:

```sh
git fetch origin
git worktree add ../doccheck-nrt-8 -b nrt-8-scaffold origin/main
```

Если пользователь просит работать в одной указанной директории, это требование имеет приоритет: новый worktree не создаётся. Перед изменениями проверять состояние Git, сохранять чужую работу и контролировать итоговый diff; при одновременной работе координировать изменения и не перезаписывать результаты друг друга. Не коммитить чужие изменения. Согласовывать одновременные изменения схемы и общих файлов.

## Проверки

Из корня репозитория:

```sh
git diff --check
git status --short
```

Проверять реально затронутое поведение и фиксировать результаты проверок. Команды проверки frontend приведены в `frontend/README.md`, каркаса backend — в `backend/tests/README.md`, контракта — в `contracts/README.md`. Эти проверки относятся к синтетическому каркасу и контракту; они не подтверждают готовность OCR или реальной сверки. Успешная проверка схемы не доказывает смысловую корректность денежных расчётов.

## Передача результата

В PR указать ID задачи, изменение поведения, команды и реальные результаты проверок, оставшиеся ограничения. Не помещать туда исходные документы и закрытые логи. Предметную приёмку проводит владелец направления. Готовый результат передаётся в In Review с меткой `review`; Done означает человеческую приёмку. Новые задачи агент создаёт только в Backlog. Без явного указания пользователя агент не пушит в `main` и не выполняет деплой.

Если нужен ответ человека, агент оставляет в соответствующей задаче Linear один вопрос с рекомендацией и ставит метку `нужна-инфа`. Вопрос адресуется владельцу направления из `AGENTS.md`; до ответа независимая работа продолжается, а зависящее от ответа решение не принимается по предположению.

Агент-автор перед созданием или обновлением PR читает связанную задачу в Linear и переносит в описание её ID, ссылку, цель, область работы и полный список актуальных критериев приёмки. Указывает дату или время получения задачи; при изменении задачи обновляет контекст в PR. Если Linear недоступен или какие-то критерии нельзя публиковать по правилам данных, явно отмечает это и не выдумывает требования; вопрос передаётся владельцу. Не помещать в PR секреты, закрытые данные, OCR-текст или независимый эталон.

Агент оставляет в `docs/agent-runs/` краткий отчёт: задача, изменённые файлы, выполненные проверки и их результаты, ограничения и следующий шаг. Исполнитель не мёржит PR и не переводит задачу в Done. В согласованном ночном запуске координатор может объединять только проверенные PR в специально выделенную ночную ветку по [порядку ночной работы](docs/agents/nightly/README.md); `main` и Done остаются человеку.

Для отдельно выбранной работы на одном устройстве см. [режим двух чатов](docs/agents/two-chat/README.md): исполнитель передаёт PR независимому ревьюеру и берёт следующую независимую задачу. Этот режим не меняет ночной регламент и не даёт дополнительного разрешения на слияние в `main` или деплой.

Николай принимает интеграцию. Агенты могут самостоятельно подготовить и независимо проверить технический контракт для ночной ветки; владельцы обработки и интеграции проверяют его при человеческой приёмке. Продуктовые неизвестные и недоступные данные не заменяются догадками. Андрей проводит независимую проверку данных и результата.

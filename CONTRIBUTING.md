# Работа над DocCheck

Базовая ветка — `main`. Начальный каркас опубликован одним коммитом; дальнейшая работа выполняется через отдельные ветки и pull request.

## Одна рабочая директория на активного агента

Перед началом прочитать задачу Linear, её критерии, зависимости и `AGENTS.md`. Ветка называется `nrt-<номер>-<краткая-тема>`. Для параллельной работы каждый агент использует собственную ветку и worktree:

```sh
git fetch origin
git worktree add ../doccheck-nrt-8 -b nrt-8-scaffold origin/main
```

Не запускать двух изменяющих код агентов в одном worktree. Не коммитить чужие изменения. Согласовывать одновременные изменения схемы и общих файлов.

## Проверки

Из корня репозитория:

```sh
git diff --check
git status --short
```

Для frontend выполнить из каталога frontend: `npm ci`, `npm run typecheck`, `npm test`, `npm run build:demo`. Обычная сборка `npm run build` должна исключать demo-модуль и его документы. Изменения интерфейса проверять в обеих темах браузером.

Каноническая схема ещё не импортирована. Тесты API, расчётов, OCR и CI появятся вместе с соответствующими модулями. Тесты форматирования интерфейса не доказывают корректность денежных расчётов.

## Передача результата

В PR указать ID задачи, изменение поведения, команды и реальные результаты проверок, оставшиеся ограничения. Не помещать туда исходные документы и закрытые логи. Предметную приёмку проводит владелец направления. Готовый результат передаётся в In Review; Done означает человеческую приёмку.

Николай принимает интеграцию. Общий контракт меняется с согласованием владельца ядра. Андрей проводит независимую проверку данных и результата.

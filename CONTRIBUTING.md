# Работа над DocCheck

Базовая ветка — `main`. Начальный каркас опубликован одним коммитом; дальнейшая работа выполняется через отдельные ветки и pull request.

## Рабочая директория и ветка

Перед началом прочитать README, задачу Linear, её критерии, зависимости и относящиеся к ней документы. Агенты также следуют `AGENTS.md`. Объём работы и приёмка определяются задачей и указаниями владельца направления. Ветка называется `nrt-<номер>-<краткая-тема>`. По умолчанию для каждого активного агента создаются отдельная ветка и папка worktree:

```sh
git fetch origin
git worktree add ../doccheck-nrt-8 -b nrt-8-scaffold origin/main
```

Если пользователь просит работать в одной указанной директории, это требование имеет приоритет: новый worktree не создаётся. Перед изменениями проверять состояние Git, сохранять чужую работу и контролировать итоговый diff; при одновременной работе координировать изменения и не перезаписывать результаты друг друга. Не коммитить чужие изменения. Согласовывать одновременные изменения схемы и общих файлов.

## Проверки

Из корня репозитория:

```sh
git diff --check
git status --short
```

Проверять реально затронутое поведение и фиксировать результаты проверок. Сейчас доступна только проверка diff. Схема и фикстура ещё не согласованы и не импортированы; проверка контракта добавляется после его согласования. Тесты API, расчётов, OCR, сборка frontend и CI ещё не реализованы; команды для них добавляются вместе с соответствующими модулями. Успешная проверка схемы не доказывает смысловую корректность денежных расчётов.

## Передача результата

В PR указать ID задачи, изменение поведения, команды и реальные результаты проверок, оставшиеся ограничения. Не помещать туда исходные документы и закрытые логи. Предметную приёмку проводит владелец направления. Готовый результат передаётся в In Review; Done означает человеческую приёмку.

Агент оставляет в `docs/agent-runs/` краткий отчёт: задача, изменённые файлы, выполненные проверки и их результаты, ограничения и следующий шаг. Агент не мёржит PR и не переводит задачу в Done.

Николай принимает интеграцию. Общий контракт меняется с согласованием владельца ядра. Андрей проводит независимую проверку данных и результата.

# Правила работы с frontend

Корневой `AGENTS.md` и `CONTRIBUTING.md` действуют для всего проекта; этот файл дополняет их правилами интерфейса.

## Архитектура

Используем Feature-Sliced Design (FSD). Начинаем с `app`, `pages` и `shared`; пустые папки не создаём. Слои `widgets`, `features` и `entities` добавляем, когда они упрощают реальную задачу, а не заранее.

- `app` — запуск приложения, провайдеры, маршрутизация и глобальное оформление.
- `pages` — страницы и код, относящийся только к ним.
- `shared` — переиспользуемые компоненты дизайн-системы (`ui`), инфраструктура API (`api`), общие функции и хуки (`lib`), общие стили и переменные оформления (`styles`). Создавать сегменты по мере необходимости.
- Общую оболочку приложения размещать в `app`; универсальные компоненты компоновки — в `shared/ui`. Крупные продуктовые блоки можно выделить в `widgets`, когда это оправданно.
- Код функции, хуки, типы и DTO хранить рядом с местом использования. Выносить в общий слой только при обоснованном переиспользовании; DTO для общих запросов размещать рядом с соответствующим API-кодом. Не создавать общий каталог для каждого вида файлов без необходимости.
- Соблюдать направление зависимостей FSD: код среза использует свой код и нижележащие слои, но не другие срезы того же слоя или слои выше. `app` и `shared` организованы сегментами, а не бизнес-срезами.

## TypeScript и читаемость

- Для описания структуры объектов предпочитать `interface`. Использовать `type`, когда `interface` не подходит, например для union, пересечений или преобразований типов.
- Не закреплять DTO по догадке: они должны соответствовать согласованному контракту API. Временные примеры явно помечать и не выдавать за утверждённый контракт.
- Простые тернарные выражения допустимы. Сложные и вложенные тернарные выражения, которые трудно читать, заменять на `if / else`, ранний выход или понятную комбинацию условий.
- Для отсутствующих значений предпочитать явные проверки и сужение типа, когда это упрощает чтение; обращаться к полю или вызывать функцию после проверки. Короткие цепочки и `?.` или `??` допустимы, если их смысл очевиден. Проверку выбирать по смыслу: не смешивать `null` и `undefined` с допустимыми значениями `0`, `false` и пустой строкой.

# Проверки backend

Из `backend` после `uv sync --frozen`:

```sh
export DOCCHECK_TEST_DATABASE_URL='postgresql+psycopg://doccheck_test:local-password@127.0.0.1:5432/doccheck_test'
uv run --frozen pytest tests/test_scaffold_integration.py -v
```

В PowerShell переменная задаётся через `$env:DOCCHECK_TEST_DATABASE_URL = '...'`.
Использовать отдельную локальную тестовую базу PostgreSQL. Учётной записи нужны
права на создание схем. Тест создаёт случайную схему `nrt8_test_<uuid>`, применяет
к ней Alembic и передаёт тот же `search_path` API и worker. В `finally` удаляется
только эта созданная схема; общие таблицы и сама база не удаляются. При аварийном
завершении процесса теста его схема может остаться для ручной очистки.

Проверяются настоящие процессы HTTP API и worker, PostgreSQL, миграция,
сохранение задания после перезапуска API, переходы `queued → processing →
completed`, отсутствие обработки без worker и отзывчивость API во время
синтетической задержки. Также проверяются некорректный/несуществующий ID,
пустая очередь и безопасная ошибка при недоступной БД. На Windows процессы
запускаются без отдельного окна и завершаются после теста.

Без `DOCCHECK_TEST_DATABASE_URL` сценарии, требующие PostgreSQL, явно пропускаются.
Такой прогон не доказывает интеграцию. Эти тесты не используют SQLite, OCR,
модель, первичные документы или независимый эталон. Результат обработчика
явно синтетический.

`uv run --frozen pytest tests/test_run_worker.py -v` проверяет очередь
сохранённых пакетов на PostgreSQL с детерминированным тестовым адаптером.
Проверяются сохранение результата, частичные ошибки, безопасный сбой,
одновременный запуск двух worker и восстановление после принудительной
остановки отдельного процесса.

Тесты `tests/ml_module/` принадлежат переданному модулю и запускаются отдельно
по его README и workflow `ml-module.yml`.

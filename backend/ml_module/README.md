# Модуль чтения и проверки реквизитов

`doccheck-ml` 0.1.0 — передаваемый backend-разработчику код без весов. Пакет
содержит существующие правила identity v2–v5 и отдельный загрузчик Qwen/LoRA.
Его можно установить, вызвать и проверить на CPU без весов.
Для настоящего inference отдельно нужны разрешённые готовые веса и проверка качества.
В ночном запуске действует `ML: no_training`: обучение, дообучение и обновление
обучаемых параметров запрещены; исходные веса не перезаписываются.

Это частичная передача по [NRT-92](https://linear.app/andreiakimov/issue/NRT-92/izuchit-gotovyj-ml-modul-i-ego-interfejs).
Результат модуля **не является финансовым `CheckResult`**, а `completed` означает
завершение обработки наблюдений, не подтверждение правильности документа.
Полная сверка, HTTP API и worker относятся к следующим интеграционным задачам.

## Проверенная версия и известные ограничения

[Аудит NRT-92](../../docs/ml-module-audit.md) выполнен на коде из PR #8,
вошедшем в базу `4440a4fa51775cd7d0e32b94b55ec55a91984087`.
Установка без модели и синтетический CLI проверены. Три замечания PR #8
воспроизведены и пока **не исправлены**:

- дата договора в заголовке может подменять дату документа;
- многоточие в номере `17...` теряется, и неполный номер принимается как `17`;
- отрицательный итог не извлекается из строки; положительное предложение модели
  при этом может оставаться в `facts.amount` без подтверждения источником.

Пять тестов `test_nrt92_audit.py` описывают корректное поведение и помечены
`expectedFailure`. Их ожидаемое падение фиксирует дефекты, а не готовность ядра.
После исправления соответствующий декоратор нужно удалить. `completed`,
`usable_value` и пустая очередь ручной проверки не доказывают правильность
всех реквизитов или пригодность к финансовой сверке.

## Что уже можно использовать

| Часть | Реальное поведение |
| --- | --- |
| `process_documents` | Проверяет SHA исходных файлов, обрабатывает уже извлечённые строки и предложения модели; возвращает реквизиты, evidence, группы и очередь проверки. |
| Identity v5 | Сохраняет исходные правила номера, запрет новых автоматических объединений по повторному чтению и отзыв неподтверждённого OCR-префикса. |
| `QwenReader.read` | Читает номер и дословную строку из локального PNG/JPEG-фрагмента; возвращает предложение и контрольные суммы модели/адаптера/изображения. |
| `doccheck-ml demo` | Явно синтетический пример без модели, GPU и исходных документов. Не используется как fallback рабочего режима. |

Пакет сам не извлекает страницы из PDF/DOCX/XLSX, не запускает PaddleOCR или
Tesseract, не находит координаты фрагмента, не агрегирует КФЗ, не отбирает договор
и период и не реализует хранение заданий. Эти этапы должны дать ему наблюдения.
Отдельные операции нормализации денег используют `Decimal`; это не финансовый
движок. Все неизвестные поля остаются `null`.

## Установка и проверка без модели

Из корня репозитория, Python 3.12 или новее:

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install ./backend/ml_module
.venv/bin/python -m unittest discover -s backend/tests/ml_module -v
.venv/bin/doccheck-ml demo
```

Базовая установка не требует MLX, модели или GPU. Демо создаёт временный
синтетический текст, обрабатывает два экземпляра одних байтов и явно возвращает
`synthetic: true`. Тесты не скачивают модель и не запускают обучение.

## Вызов из worker

Worker вызывает Python-функцию вне HTTP-запроса. Пути должны быть выданы локальным
хранилищем задания, а не взяты напрямую из запроса пользователя.

```python
from pathlib import Path
from doccheck_ml import DocumentInput, process_documents

# Все значения ниже получает ваш парсер/OCR при чтении исходного файла.
document = DocumentInput(
    id=document_id,
    source_path=Path(stored_file),
    source_sha256=sha256_at_extraction,
    acquisition="scan",  # "native" только для настоящего нативного текста
    lines=extracted_lines,
    prediction=model_prediction,  # словарь; отсутствующие значения — None
)
result = process_documents([document])
```

`lines` — список словарей с обязательным `text`; адрес источника задаётся через
`page`/`line` (с 1), `sheet`/`cell`, опциональные `bbox`, `score`, `image`.
`bbox` здесь — координаты исходного OCR, а не автоматически нормализованные
координаты общего HTTP-контракта. Их преобразует адаптер, знающий размер страницы.
Текст и координаты должны относиться к файлу с переданным SHA. Проверка SHA
обнаруживает замену файла после извлечения, но не доказывает правильность OCR.
При объединении подписи и значения, а также привязке отдельной строки номера к
заголовку требуется общая явно указанная страница или лист. Разные страницы/листы,
отсутствующий адрес, пропуски нумерации строк и несоседние ячейки не склеиваются.
Если переданы номера строк или адреса ячеек, они нужны у обоих фрагментов;
ячейки одного листа должны непосредственно соседствовать справа или снизу. В
`fact_evidence` первичного извлечения сохраняется список всех использованных
строк, включая строку самого значения.

Маркер номера, относящийся к договору или контракту в заголовке, не считается
номером документа. Отдельно указанный номер акта сохраняется, даже если его
значение совпадает с номером договора. После явной подписи номера допускается
знак `№`; буквенные префиксы самого номера `N`/`No` сохраняются. Пустая подпись
исполнителя использует следующую строку только при той же проверке адресов.

Явный итог (`Итого`, `Итоговая сумма`, `К оплате`, `Сумма по акту`) имеет приоритет
над общими полями `Сумма`/`Стоимость`, независимо от порядка строк. Если итогов
нет, используется однозначное общее поле. Явные целые суммы, включая 0 и 1–9,
извлекаются из источника. Если в `source_facts` отсутствует ключ `amount`, поле
`facts.amount` может содержать `null` или строку `prediction.amount` без проверки
денежного формата. Перед использованием проверьте формат и наличие подтверждения
в `source_facts`. При нечитаемом итоге промежуточную сумму нельзя считать итоговой.

Разные значения выбранной роли, а также сочетание читаемого и нечитаемого итога
дают `facts.amount = source_facts.amount = null`. В `fact_conflicts.amount`
сохраняются причина и все кандидаты с адресами, в `fact_evidence.amount` — их
исходные строки. Равные значения сравниваются через `Decimal`. Конфликт виден
в `review_queue.fact_review_document_ids` и `fact_cards` даже для одного документа;
он не снимается совпавшим ответом модели или повторным чтением одного фрагмента.

В `prediction` допустимы строковые значения или `None`: `doc_number`,
`verbatim_line`, `contract_number`, `date`, `period_start`, `period_end`, `amount`,
`category`, `description`, `evidence_quote`. Нельзя передавать независимый эталон.
Результат модели не получает статус подтверждения только из-за успешного вызова.

Выход версии `doccheck-ml-identity/1` содержит `records`, `groups`, `review_queue`,
`errors`, `policy_version`, `synthetic` и признак `inference_performed: false`:
**сама функция** модель не вызывает. `number.value` — предложение;
`number.usable_value` — значение, допущенное текущей identity-политикой.
Это не статус достоверности финансового показателя. Evidence и текст результата
хранятся локально и не должны попадать в публичные логи.

Автоматическая группировка в публичном API действует только для одинакового
SHA-256. `DocumentInput` не принимает `content_fingerprint` и `package_fingerprint`.
Разные байты при совпавших реквизитах могут дать `candidate` с `auto_merge=false`
в `groups.review_pairs`. Исходные файлы сохраняются.

Некорректный манифест вызывает `InputError`. Недоступный или изменённый файл
даёт `source_unavailable`/`source_changed` в `errors`, исключается из групп;
остальные документы продолжают обрабатываться, общий статус — `partial`.

### Повторные чтения

Верхнеуровневая функция пока не принимает сохранённые benchmark-пакеты или
произвольные флаги подтверждения. Для осторожной интеграции доступны низкоуровневые
`doccheck_ml.identity.identity_v3/v4/v5`: они принимают **доверенные, проверенные
worker-наблюдения**. Их формы видны в синтетических тестах `test_identity*`.
Нельзя подавать в них JSON непосредственно от клиента или считать совпадение
двух вариантов Tesseract двумя независимыми OCR-движками.

В v4 исправление итоговой суммы теперь получает явный аргумент
`source_observation={"id": ..., "source_sha256": ..., "lines": [...]}`.
Файлы по `paddle_provenance.cache` больше не читаются. Без явных наблюдений
исправление суммы пропускается. Правила и порог уверенности 80 сохранены;
хеш наблюдения не заменяет проверку его происхождения.

## Подключение готовых весов для inference

Текущий reader перенесён из MLX-эксперимента на Python 3.12/macOS Apple silicon.
Совместимость с Linux/CUDA и контейнером backend пока не проверена. Доступные
backend-окружения и транспорт следует проверить при интеграции; установка
CPU-пакета сама по себе не означает работоспособность MLX-инференса.

В отдельном окружении подготовить зависимости и локальные веса до рабочего
запуска:

```sh
python -m pip install './backend/ml_module[mlx]'
```

```python
from pathlib import Path
from doccheck_ml.qwen import QwenConfig, QwenReader

reader = QwenReader(QwenConfig(
    model_dir=Path("/local/models/qwen-base"),
    adapter_path=Path("/local/models/approved-adapter/adapters.safetensors"),
))
observation = reader.read(Path("/local/jobs/job-1/number-crop.png"))
model_prediction = observation["prediction"]
```

База эксперимента: `mlx-community/Qwen3.5-4B-MLX-4bit`, ревизия
`32f3e8ecf65426fc3306969496342d504bfa13f3`. Reader ожидает локальный каталог с
`model.safetensors`, `config.json`, tokenizer/processor-конфигурациями и
`chat_template.jinja`; конкретный список проверяется в `qwen.MODEL_FILES`.
Дополнительные файлы `.safetensors` запрещены. Если есть индекс весов, он может
ссылаться только на `model.safetensors` и сам включается в контрольные суммы.
Рядом с выбранным адаптером нужен его `adapter_config.json`.
`adapter_path=None` означает **явно выбранную базу**. Если указанный адаптер
отсутствует или не восстановился точно, вызов завершается ошибкой без fallback.
Импорт и создание reader не запускают модель; загрузка происходит на первом
`read`. Один экземпляр предназначен для последовательного worker. Файлы модели
и адаптера должны оставаться неизменными в течение его жизни.

Ошибки: `QwenInputError` (изображение), `QwenUnavailableError` (веса/окружение),
`QwenPredictionError` (сбой, обрезанный ответ или неверный JSON). Ответ включает
SHA изображения, файлов модели, адаптера и его конфигурации, prompt/policy/request.
Привязку фрагмента к оригинальному документу и его координаты обеспечивает worker.
Успешный `read` не подтверждает номер автоматически.

Параметры перенесены из существующего reader: greedy, 128 токенов, прежние prompt,
JSON-структура и границы изображения. Лимит MLX в 9 GiB — настройка, **не измеренная
минимальная RAM/VRAM**. Тесты этого пакета проверяют интерфейс на подменённом runtime;
реальный прогон выбранного адаптера и измерение качества/памяти ещё обязательны.

В Git не входят веса, обучение, OCR-кэши, датасеты и результаты экспериментов.
Для подключения передать отдельно разрешённый готовый checkpoint,
`adapter_config.json`, SHA, лицензию и имеющийся отчёт качества. Это не разрешение
на обучение; выбор checkpoint и подтверждение качества остаются за владельцем.

Документация runtime: [MLX-VLM](https://github.com/Blaizzy/mlx-vlm) и
[использование локальных моделей](https://github.com/Blaizzy/mlx-vlm/blob/main/docs/usage.md).
Закреплённые версии соответствуют локальному эксперименту; при обновлении нужен
новый прогон совместимости.

## CLI для наблюдений

```sh
doccheck-ml process --manifest /local/job/manifest.json --output /local/job/result.json
```

Манифест: объект с `schema_version: "doccheck-ml-input/1"`, явным `synthetic`
и списком `documents` с полями `DocumentInput`. Пути `source_path` относительные
и должны оставаться внутри каталога манифеста, включая цели символических ссылок.
Выходной файл должен быть новым. После разбора аргументов код выхода:
0 — обработано; 2 — есть ошибки файлов; 1 — некорректный манифест/ошибка записи.
Ошибки аргументов `argparse` также возвращают 2 до обработки, поэтому этот код
сам по себе не подтверждает частичный результат. Результат содержит исходные фрагменты,
поэтому сохраняется локально; stdout процесса содержит только счётчики.

# Пробное AI-ревью в GitHub Actions

Workflow `.github/workflows/neuro-review.yml` запускает отдельный Codex через API-ключ при открытии, обновлении или переводе PR в готовый вид, а также вручную по номеру PR. Он получает описание задачи из Linear и передаёт его ревьюеру; для проверки используются инструкции и схема из base PR. Ревьюер читает отдельно полученный head и не выполняет код или тесты PR. Вердикт, замечания и ограничения публикуются комментарием; неуспешное или неполное ревью завершает проверку ошибкой. Новое изменение head требует нового ревью.

## Подготовка

1. Репозиторий и GitHub Actions должны работать у актуального владельца. Добавить workflow, инструкцию и схему в base-ветку PR: запуск не может прочитать их из base до публикации.
2. В GitHub открыть репозиторий → Settings → Secrets and variables → Actions → New repository secret. Имя: `OPENAI_API_KEY`; значение: API-ключ OpenAI Platform. Не помещать ключ в Git, PR, чат или логи. При передаче репозитория проверить наличие секрета и права нового владельца.
3. В Linear открыть Settings → Account → Security & Access, создать отдельный API-ключ только на чтение с доступом к команде NRT и задачам проекта. Создать в GitHub Actions repository secret `LINEAR_API_KEY`. Ключ использует права создавшего его пользователя и должен иметь доступ к нужной задаче; не помещать его в Git, чат, PR или логи.
4. В заголовке или описании открытого PR из этого же репозитория указать ровно один уникальный ID задачи `NRT-...`. Не размещать там секреты или закрытые данные. Объединение нескольких задач в один PR в первой версии не поддерживается.
5. После события PR проверка появится в GitHub Actions; для ручного прогона открыть Actions → Independent AI review → Run workflow, выбрать ветку, содержащую workflow, и указать номер PR.

## Как читать результат

- `pass` — нет найденных блокирующих проблем в проверенном объёме; это не человеческая приёмка.
- `changes_requested` — найдены существенные замечания; нужна доработка и повторная проверка.
- `blocked`, ошибка подготовки, пропущенный запуск или ошибка модели — ревью не завершено и не должно считаться успешным.

Отдельный шаг получает название и описание конкретной задачи из Linear GraphQL API; только этот шаг видит ключ Linear. Ревьюер получает текст задачи на момент запуска, но не получает ключ и не имеет прямого MCP-доступа ко всему Linear. Текст задачи передаётся в OpenAI API для ревью: включать в задачи только информацию, разрешённую для такой передачи. Приложенные документы, комментарии, связанные задачи и изменения задачи после начала запуска автоматически не проверяются. Если они необходимы для принятия решения, результат должен быть `blocked`. Публикация непубличного содержания задачи в GitHub запрещена. Если ключ, задача или доступ отсутствуют, проверка завершается ошибкой.

Команда и результат относятся к точным base/head SHA; если PR меняется во время ревью, результат отклоняется. Браузерные тесты, код PR и реальные документы workflow не запускает, а исправления не вносит. Внешние fork пока не поддерживаются. Отдельный CI тестов остаётся независимым.

API-ключ использует API-биллинг, который отличается от лимитов ChatGPT. Запуски Codex с API-ключом не покрываются бонусом API-кредитов, привязанным к подписке; проверить баланс и лимиты API до запуска. Модель и стоимость ревью зависят от доступного API и объёма кода.

Конфигурация подготовлена, но не проверена настоящими запросами с ключами Linear и OpenAI и не запущена в GitHub Actions. Если GitHub блокирует выполнение по биллингу, после передачи владельцу нужно сначала проверить доступность Actions.

# Закрытый Preview: Vercel, Render и модель на компьютере

Гибридный Preview показывает результат реальной сверки встроенного
синтетического комплекта XLSX + DOCX. Render хранит задания и результаты
в отдельной PostgreSQL. Воркер сам обращается к Render по HTTPS и вызывает
Ollama на `127.0.0.1:11438`. Входящие подключения к компьютеру с моделью
не нужны. Режим приглашений привязывает отдельное задание к каждому участнику.
Ручная загрузка в облако потребует отдельного решения по допуску и хранилищу.
Полностью локальный запуск описан в [README](../README.md).

## 1. API и PostgreSQL

1. Запишите полный SHA проверенного коммита. Создайте отдельную ветку
   для Preview на этом SHA и оставьте её неподвижной на время подготовки.
   Проверьте её серверный SHA через `git ls-remote origin refs/heads/<ветка>`
   перед применением Blueprint.
2. В отдельном Render workspace со свободным бесплатным PostgreSQL откройте
   **New Blueprint**, выберите этот репозиторий и эту ветку. Укажите
   **Blueprint Path** `render.hosted-preview.yaml`. После создания отключите
   **Auto Sync** у Blueprint отдельно от **Auto-Deploy** сервиса. В Dashboard
   проверьте SHA первой сборки, единый регион и отключённый внешний доступ к
   БД. При расхождении SHA остановите Preview и примените ручной деплой
   проверенного коммита.
3. Подготовьте три вида секретов. Для каждого токена и ключа независимо
   сгенерируйте 32 случайных байта, записанных в hex. Храните их в
   менеджере секретов. Для каждого приглашения создайте отдельный UUID.

   | Переменная | Что передать |
   | --- | --- |
   | `DOCCHECK_HOSTED_WORKER_SHA256` | Render получает SHA‑256 ASCII-строки токена воркера в нижнем регистре, без перевода строки. Токен получает оператор компьютера. |
   | `DOCCHECK_HOSTED_VIEWERS` | Render получает JSON-объект `{"<UUID>":"<SHA-256 ASCII-строки приглашения>"}`. Каждый участник получает своё исходное приглашение. |
   | `DOCCHECK_HOSTED_SESSION_KEY` | Render получает отдельный 64-символьный hex-ключ подписи cookie. |

4. Дождитесь `GET https://<имя-сервиса>.onrender.com/health` с HTTP 200 и
   `{"status":"ok","database":"ok"}`. При запуске API проверяет БД и роль,
   применяет миграции и ставит в очередь по одному встроенному комплекту на
   участника. Облачная роль ещё требует проверки: старт отклонит
   `CREATEDB`, `CREATEROLE`, другие повышенные права и членство в ролях.
   Если журнал сообщает `Render Preview database isolation could not be verified`,
   проверьте роль на выделенном экземпляре. Привилегии и конфигурация
   публичного демо в этом запуске не используются.

## 2. Сайт

1. Создайте выделенный проект Vercel с **Root Directory** `frontend`, Vite и
   Node.js 24. Для Preview включите Vercel Authentication и выдайте
   участникам доступ. Для проверки двух сеансов на Hobby используйте владельца
   проекта и одного допущенного внешнего участника. Публикация идёт вручную
   из проверенного коммита.
2. Задайте в окружении **Preview**:

   | Переменная | Значение |
   | --- | --- |
   | `DOCCHECK_HOSTED_PREVIEW` | `1` |
   | `DOCCHECK_PREVIEW_RENDER_ORIGIN` | HTTPS origin API Render без пути или завершающего слеша |

3. Из корня чистого worktree привяжите CLI к выделенному проекту. Сверьте
   имя проекта при привязке. Конфигурация `frontend/vercel.mjs` собирает
   отдельную страницу и проксирует `/api/preview/v1/*` к Render. В Vercel
   передаются только указанные настройки сборки.

   ```sh
   vercel link --project doccheck-hosted-preview
   vercel pull --environment=preview
   vercel build
   vercel deploy --prebuilt
   ```

   Откройте URL именно Preview из ответа CLI.

[Настройки проекта Vercel](https://vercel.com/docs/project-configuration/project-settings) ·

## 3. Компьютер с моделью

Возьмите тот же коммит, что на Render. Подготовьте Ollama и закреплённую Qwen
по [инструкции v3.2](../bench/e2e_v32_20261114/README.md). Из корня репозитория
запустите PowerShell 7.2+ и выполните:

```powershell
./scripts/run-v32-hosted-worker.ps1 -RenderOrigin 'https://<имя-сервиса>.onrender.com' -Once
```

Скрипт проверит готовность API и digest локальной модели, затем запросит
токен скрытым вводом. Можно передать токен через окружение процесса в
`DOCCHECK_HOSTED_WORKER_TOKEN`. Для одного показа повторите `-Once` по
числу ожидающих участников. Без `-Once` воркер опрашивает очередь постоянно.
На бесплатном Render постоянный опрос расходует часы сервиса. БД и Ollama
остаются за своими сетевыми границами.

Для Linux и macOS выполните из корня репозитория с токеном в окружении:

```sh
uv run --project backend --locked --with-requirements bench/e2e_v32_20261114/requirements.txt python -m doccheck_backend.hosted_worker --origin 'https://<имя-сервиса>.onrender.com' --processor doccheck_backend.v32_adapter:process --once
```

## 4. Проверка и откат

- Войдите по приглашению на Vercel, убедитесь, что видна одна проверка.
  Запустите воркер, обновите список и дождитесь результата. Пустая очередь
  также даёт код 0 у `-Once`. Статус «Обработка» означает, что задание уже
  выдано воркеру или ждёт истечения аренды. «Готово», «Готово с замечаниями»
  и «Ошибка» означают, что обработка завершена.
- Для нового показа после завершения создайте новый UUID и приглашение.
  Примените обновлённый список зрителей к выделенному API и дождитесь
  нового задания. UUID и SHA манифеста определяют ключ запуска, поэтому
  перезапуск API и смена приглашения при прежнем UUID новое задание не создают.
  Удалите временный UUID из настроек после показа и примените конфигурацию.
- Откройте источник и скачайте оригинал и XLSX. Перезагрузите страницу и
  проверьте сохранение сессии. В отдельном браузерном профиле с другим
  приглашением запрос чужого результата должен вернуть 404.
- Запишите SHA, URL обоих компонентов и итоги проверки. Для возврата версии
  остановите воркер, отзовите доступ к Vercel Preview и приостановите выделенный
  API Render. Проверьте совместимость прежнего SHA с текущими миграциями БД.
  Используйте новый ручной деплой выбранного SHA с актуальным списком
  приглашений, digest токена и ключом сессии. Кнопка **Rollback** на Render
  восстанавливает старый снимок переменных и может вернуть отозванный доступ.
- Перед выдачей ссылки снова проверьте `/health` и убедитесь на прямом
  API Render, что отозванные приглашение, cookie и токен воркера отклоняются,
  а действующее приглашение открывает только свой результат. Затем откройте
  доступ к совместимому Vercel Preview и запустите воркер.

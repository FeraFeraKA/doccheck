# Граница вызова ML-модуля из worker

Граница отдельного модуля — пакет `doccheck-ml 0.1.0`, результат
`doccheck-ml-identity/1`, политика `identity-v5.0-prefix-guard`.
Текущий адаптер v3.2 использует отдельный конвейер и не вызывает этот модуль.
[Адаптер v3.2](../backend/src/doccheck_backend/v32_adapter.py) ·
[Контракт результата](result-source-contract.md)

## Вызов и вход

Пакет предоставляет синхронный вызов `doccheck_ml.process_documents` для
обработки подготовленных наблюдений. При возможном подключении к отдельному
Python worker обработчик должен получать задание из PostgreSQL, разрешать ID
файлов в локальные пути и подготавливать наблюдения до вызова модуля. Для
вызова модуля не нужна активная транзакция БД.
[API модуля](../backend/ml_module/src/doccheck_ml/api.py)

```python
from doccheck_ml import DocumentInput, process_documents

# В этом примере worker получил все наблюдения из текстового слоя.
document = DocumentInput(
    id=document_id,
    source_path=source_path,
    source_sha256=source_sha256,
    acquisition="native",
    lines=lines,
)
result = process_documents([document], synthetic=False)
```

`process_documents(documents, *, synthetic=False)` принимает
последовательность `DocumentInput`. `synthetic` относится ко всему
вызову. Для вымышленных входов его явно выставляют в `True`.

| Вход | Смысл и проверка |
| --- | --- |
| `id`, `source_path`, `source_sha256` | Непустой уникальный ID, `pathlib.Path` и 64 строчных шестнадцатеричных символа SHA-256 файла на момент извлечения. Worker выбирает путь внутри хранилища задания. Python API доверяет этому пути и сверяет текущие байты с SHA. Дайджест связывает версию файла с наблюдениями по заявлению worker. Соответствие строки содержимому требует отдельной проверки. |
| `acquisition` | Одно значение на `DocumentInput`. Использовать `native`, если все передаваемые наблюдения получены нативным извлечением. Если в одном входе есть OCR-наблюдения, включая смесь нативных и OCR-фрагментов, передавать `scan`. Worker хранит происхождение каждого фрагмента отдельно для проверки и формирования доказательств. Поле `acquisition` внутри `lines` публичный API отклоняет. |
| `lines` | Упорядоченный список словарей со строкой `text`. Допустимы `page`, `line` от 1, строковые `sheet`, `cell`, `image`, конечный `score`, упорядоченный `bbox` из четырёх конечных координат. Порядок может менять выбор первого кандидата и склейку соседних строк. Данные расположения проверяет адаптер. |
| `prediction` | Необязательный словарь. Допустимы `doc_number`, `verbatim_line`, `contract_number`, `date`, `period_start`, `period_end`, `amount`, `category`, `description`, `evidence_quote` со строками или `null`. Поле выражает предположение, которое нужно сверить с источником. |

Метка влияет на доверие к номеру документа. В проверенном примере с
нативным заголовком и номером из OCR вход с меткой `native` получил статус
`native_source` и заполненный `usable_value`. Вход с меткой `scan`
получил `ocr_source_only`, `usable_value=null` и признак ручной проверки.

Модуль читает исходные байты для SHA и обрабатывает переданные наблюдения.
Извлечение строк из PDF, PNG, XLSX и DOCX, чтение таблицы КФЗ и OCR страниц
выполняют отдельные компоненты. Для локальной диагностики доступен
`doccheck-ml process --manifest … --output …` с манифестом
`doccheck-ml-input/1`. Пути источников ограничены каталогом манифеста.
Для каждого вызова выбирают свободный путь `--output`. Код 2 означает
частичную обработку, когда текущий вызов создал JSON со статусом `partial`
и напечатал сводку со статусом `partial` в stdout. При ошибке аргументов
CLI также возвращает 2, выводит диагностику в stderr и оставляет
существовавший файл без изменений. Занятый путь вывода при корректных
аргументах даёт код 1.
[CLI](../backend/ml_module/src/doccheck_ml/cli.py)

## Что возвращается и как допустить наблюдение

`records` содержит номер и его `usable_value`, признаки ручной проверки,
`doc_type`, `issuer`, `facts`, `source_facts`, `fact_evidence` и
`fact_conflicts`. Верхний уровень возвращает `groups`, `review_queue`,
`errors`, `status`, версии и флаг `synthetic`. У
`process_documents` флаги `inference_performed` и
`financial_reconciliation_performed` равны `False`. Служебные вложенные
диагностики identity используются для локального разбора.
[Модуль](../backend/ml_module/src/doccheck_ml/api.py) ·
[Извлечение реквизитов](../backend/ml_module/src/doccheck_ml/identity/identity_v2.py)

| Наблюдение | Действие адаптера и ядра |
| --- | --- |
| Номер, тип и сторона с адресом | Кандидаты на `document_identity`. Сверить роль, полноту и адрес. `usable_value` означает решение политики номера модуля, а пригодность для привязки к договору подтверждается отдельно. Публичный вызов не запускает независимое перечитывание префикса. |
| `source_facts.amount` и `fact_evidence.amount` | Кандидат на `amount` с одним или несколькими фрагментами. Сверить значение, знак, единицу и роль суммы. Общий итог модуля не описывает каждую операцию в документе. Для `reported_value` нужен адрес выбранной строки КФЗ и её колонки. |
| `source_facts.contract_number` и `date` | В номер договора переносится только адресное наблюдение с проверенной ролью. Сверить все значимые чтения. В синтетике с двумя явно записанными номерами модуль сохранил первый без `fact_conflicts`. Дата документа или договора сама по себе не подтверждает период операции. |
| `facts.period_start`, `facts.period_end`, `facts.category`, другие поля `facts` | Кандидаты. `facts` объединяет предложения и найденные реквизиты. Модуль не создаёт надёжной привязки к статье или границам периода. Источник может содержать нужный смысл в назначении, строке таблицы или отдельном приложении. Нужны адрес и явное правило связи. |
| `fact_conflicts` и `review_queue` | Сохраняются как причины и доступные фрагменты. Если наблюдение нельзя проверить, зависимое значение остаётся `null`. Пустая очередь сама по себе не подтверждает значения и полноту. |
| `groups.groups` и `groups.review_pairs` | Публичный вызов автоматически объединяет только одинаковые SHA-256. Пары разных байтов с `auto_merge=false` остаются кандидатами или конфликтами. Worker сохраняет реестр всех экземпляров. Для побайтовой копии указывает представителя, а из него допускает каждую самостоятельную операцию один раз. Равные суммы у разных операций сохраняются. |

Для подтверждения отдельной операции нужны самостоятельные основания
суммы, договора, периода и статьи. Связь может опираться на другой файл,
если её можно проверить по конкретным фрагментам и согласованному правилу.
Реквизиты отчёта задают область сверки. Они не подтверждают принадлежность
первичного слагаемого без основания связи. Ядро хранит найденную сумму
допущенных слагаемых отдельно от полного ожидаемого значения и выводит
полноту по принятому профилю или другому разрешённому основанию.
[Семантика доказательств](result-source-contract.md#адреса-доказательств-и-допуск-суммы)

Проверенное денежное значение разбирается из строки как `Decimal` или
целые копейки. Нужны конечность, поддерживаемая единица и точность по
правилу показателя. Правило округления должно быть известно до сравнения.
Денежное значение в общем контракте передаётся строкой с точкой и двумя
знаками. Явно подтверждённый ноль передаётся как `"0.00"`. При отсутствии,
конфликте или нечитаемом значении используется `null`. В модульном
`facts.amount` встречается исходная произвольная строка из prediction.
Даже строка в `source_facts.amount` требует проверки источника и роли.
При неполной или несопоставимой первичке итог остаётся `unverified`.
Только ядро присваивает `verified` или `discrepancy` после точной сверки
полных доказанных значений.
[Контракт показателей и полноты](result-source-contract.md#показатели-и-полнота)

## Адреса в общем результате

| Формат | Что передаётся через модуль | Что проверяет и преобразует адаптер |
| --- | --- | --- |
| PDF, PNG | `page`, `line`, `bbox`, `image` при наличии. Модуль возвращает переданные адреса, координаты остаются в исходной системе. | PDF использует номера страниц от 1, PNG — страницу 1. Преобразовать проверенную рамку к целой странице с учётом обрезки, масштаба, поворота и ориентации просмотра, затем нормализовать в `[0, 1]` от левого верхнего угла. Строка годится, когда её воспроизводимо находит сохранённое извлечение и она выделяет значение. Одна страница служит навигацией. |
| XLSX | `sheet`, `cell`. Модуль принимает строки, в том числе недействительный адрес. | Проверить существование листа и A1-адрес или диапазон, сохранить адреса отдельных слагаемых. Формулу без кэша пересчитывать только при поддерживаемом правиле. Отсутствие результата формулы не задаёт ноль. |
| DOCX | Публичный `lines` не принимает поля абзаца, таблицы или ячейки DOCX. | Получить позицию у парсера и связать наблюдение с её исходным абзацем или ячейкой таблицы. Хранить однозначные индексы от 1 по сохранённой версии документа. Не подменять структурный адрес номером строки произвольного текста. |

Для разрешённого комплекта это влияет на скан КФЗ с многоуровневой
шапкой, нативные и сканированные акты, формульные итоги XLSX и DOCX,
где реквизиты и суммы находятся в разных частях. В `evidence` общего
результата попадают только проверяемые фрагменты с ID документа и версией
файла. Адаптер хранит связь с версией извлечения и фактическим методом
`native` или `ocr`, чтобы тот же фрагмент можно было открыть и проверить.
Текст наблюдений и реальные результаты остаются в локальном хранилище
по правилам данных.

## Ошибки, версии и Reader

- `InputError` прерывает весь вызов до обработки при некорректной
  структуре, неизвестном поле, повторном ID или неверном типе адреса.
  Worker фиксирует ошибку входа адаптера отдельно от состояния файла.
- `source_unavailable` и `source_changed` привязаны к ID документа.
  В этом вызове документ отсутствует в `records` и группах. При
  `source_changed` нужны новые наблюдения для подтверждённой версии.
  По остальным документам обработка продолжается, модуль возвращает
  `partial`. Worker сохраняет ошибку файла и проверяет влияние на
  полноту каждой строки.
- `completed` в модуле означает вызов без этих ошибок. Даже пустой
  вход может вернуть `completed`. Worker отдельно выбирает состояние
  задания по факту сохранения пригодного результата. При сохранённом
  частичном техническом сбое используется `completed_with_issues`.
  При фатальной ошибке без пригодного результата используется `failed`.
- Опциональный `QwenReader(QwenConfig(model_dir=…, adapter_path=…)).read(…)`
  принимает локальный однокадровый PNG/JPEG фрагмент номера. Первый
  вызов лениво загружает локальную модель. Один экземпляр предназначен
  для последовательного использования. Результат содержит только
  предложения `doc_number` и `verbatim_line` в `prediction`, хеши
  входа, модели, конфигурации и запроса, а также время вызова без холодной
  загрузки. Хеш фрагмента не даёт адреса в оригинале. Отдельные ошибки
  `QwenInputError`, `QwenUnavailableError` и `QwenPredictionError`
  относятся к чтению, а не к финансовому результату.
  [Reader](../backend/ml_module/src/doccheck_ml/qwen.py)

Пакет требует Python 3.12 или новее. Путь identity работает без
опциональных библиотек модели. Reader требует локальные неизменяемые
файлы модели, при необходимости готовый адаптер и закреплённые MLX
зависимости. При ошибке выбранного адаптера переход на базовую модель
не выполняется; отсутствие необходимых весов приводит к ошибке.
[Зависимости](../backend/ml_module/pyproject.toml)

При интеграции worker должен записывать фактически использованные `code_revision`,
`rules_version`, `ml_module_version`, `ml_policy_version`,
`model_revision` по [общему контракту](result-source-contract.md).
При вызове только identity `model_revision=null`. Фактическую ревизию
готовой модели нужно подтвердить по разрешённому комплекту и его SHA.
Маркировка синтетического запуска сохраняется в общем результате.
`doccheck-ml-identity/1` остаётся форматом ответа модуля, а
`doccheck-check-result/1` — семантическим контрактом обмена. Машинные
модели и схема находятся в [общем контракте](../contracts/README.md).

При использовании модуля необходимо отдельно проверять роль даты, полноту
номера и знак суммы: дата договора может быть принята за дату документа,
номер — усечён, а отрицательный итог — пропущен. При отсутствии
подтверждения результат строки остаётся `unverified`.

При интеграции требуется сохранять происхождение наблюдений и их адреса,
связывать ошибки с документом и строкой и согласовать предметные правила
периода, полноты и замены документов.

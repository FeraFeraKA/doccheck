# Первому человеку: координатор и worker-a

Николай открывает **два отдельных чата Codex** на своём компьютере. В каждом выбран локальный проект `doccheck`; отдельный третий чат на Mac друг откроет сам. Перед запуском актуальные инструкции должны быть опубликованы в версии, доступной обоим участникам из GitHub. Координатор сообщит ночную ветку и полный SHA.

Если координатор и `worker-a` используют один каталог, координатор управляет общими ветками и PR через GitHub; он не переключает, не сбрасывает и не коммитит локальную рабочую копию, пока в ней работает `worker-a`. Ревью проводится по точным коммитам и проверкам в GitHub, а не по меняющимся локальным файлам. Если необходимых данных или проверок там нет, координатор сообщает о блокере и не объединяет PR.

## 1. Открой чат координатора

В приложении ChatGPT выбери режим Codex, открой проект `doccheck` на своём компьютере и создай отдельный чат. Убедись, что этот чат имеет доступ к Linear и GitHub. Вставь:

```text
Ты координатор полноценной ночной работы DocCheck. Прочитай README.md, docs/agents/nightly/README.md, protocol.md, communication.md, coordinator.md и review.md из этой папки. Изучи согласованную очередь и зависимости в Linear. Проверь доступы, создай общую ночную ветку от актуальной проверенной версии инструкций и опубликуй START с mode: nightly в NRT-90. Координатор и worker-a могут использовать один каталог: не переключай и не изменяй его Git-состояние во время работы worker-a; общими ветками и PR управляй через GitHub, а ревью проводи по точным коммитам и CI в GitHub. Если доказательств не хватает, укажи блокер и не объединяй PR. Сообщи мне точную ветку, коммит и run_id. Дождись моего сообщения, что оба рабочих чата готовы, прежде чем назначать им задачи.

Создай в этом чате одно плановое продолжение каждую минуту с точным коротким текстом координатора из docs/agents/nightly/macos.md; проверь сохранённый текст и фактический запуск. После подтверждения готовности автоматически распределяй готовые согласованные задачи и продолжай очередь по мере завершения зависимостей. Поручай ревью каждого PR противоположному worker и дожидайся CI и Codex Code Review по docs/agents/nightly/review.md. При блокерах продолжай независимую работу; когда свободных согласованных задач нет, используй отдельную экспериментальную ветку по protocol.md. Не вливай в main, не деплой и не помечай задачи Done. Работай до моей команды STOP или системного ограничения; при остановке опубликуй STOP и останови плановое продолжение.
```

Координатор должен сообщить название ночной ветки, полный SHA и `run_id`. Если он не смог подключить Linear/GitHub или создать плановое продолжение, автоматический запуск пока не готов.

## 2. Открой отдельный чат worker-a

Создай **новый чат**, снова выбери проект `doccheck` и вставь:

```text
Ты рабочий агент worker-a ночного запуска DocCheck. Проверь доступ к Linear и GitHub и получи активный START из комментариев NRT-90. Получи базовую ветку из GitHub и проверь полный SHA от координатора. Если рабочая копия содержит чужие незакоммиченные изменения, не переключай и не перезаписывай её, сообщи о блокере. Перейди на точную версию инструкций только если это безопасно, затем прочитай docs/agents/nightly/README.md, docs/agents/nightly/protocol.md и docs/agents/nightly/worker.md. Сообщи мне о готовности.

Создай в этом чате одно плановое продолжение каждую минуту с точным коротким текстом работника из docs/agents/nightly/macos.md, подставив worker-a; проверь сохранённый текст и фактический запуск. Выполняй действующие назначения worker-a и запросы на ревью чужого PR по docs/agents/nightly/review.md, передавай ACK, RESULT или BLOCKED и открывай PR в целевую ночную ветку назначения. Не мёрж PR, не пушь в main и не ставь Done. При STOP подтверди остановку и останови плановое продолжение.
```

Это отдельный чат, а не подагент координатора. Когда он подтвердит готовность, попроси друга выполнить [его инструкцию](second-person.md). После готовности обоих напиши координатору: **«Оба рабочих чата готовы, начинай ночную очередь»** — и укажи учётные записи Linear и GitHub друга. Координатор сверит авторов `READY` и свяжет аккаунты со слотами в `GO`.

## 3. Что проверить в начале и после остановки

- Во время назначения в NRT-90 видны `START`, два `READY`, `GO`, два назначения и `ACK` от обоих работников; один работник не взял оба задания. После подтверждённого завершения временные комментарии назначения могут исчезнуть: итог проверяй в блоке состояния и PR.
- Результаты представлены отдельными PR в ночную ветку. В каждом PR опубликован отзыв противоположного worker, CI и Codex Code Review завершились для актуальных версий; автор не публикует отдельное ревью своей работы.
- Координатор показал фактический результат обеих задач и ограничения. Отсутствие ответа или остановившийся чат не считается успешным выполнением.
- Координатор не объединял изменения в `main`. Если меняется его состояние или возникают вопросы по общему каталогу, сначала выясни их, не удаляя незакоммиченные изменения.
- Когда потребуется остановить работу, напиши координатору «Останови ночной запуск». В NRT-90 должны появиться `STOP` и `STOPPED` от каждого из `worker-a` и `worker-b` для текущего `run_id`: два повторных сообщения одного слота не считаются подтверждением другого. В разделе Scheduled («Запланировано») проверь остановку продолжений координатора и `worker-a`, а друга попроси проверить продолжение `worker-b`. После этого следующий запуск создаётся отдельно.

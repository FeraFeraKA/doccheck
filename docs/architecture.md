# Границы архитектуры

Планируемый путь данных:

```text
TypeScript UI → FastAPI → PostgreSQL (задания/метаданные)
                    ↓              ↑
            локальные файлы → Python worker
                                   ↓
                         process_package → CheckResult
                                   ↓
                           PostgreSQL → API → UI
```

API не выполняет OCR в процессе обработки HTTP-запроса. Отдельный worker резервирует задания в PostgreSQL; начальная параллельность — один пакет. Оркестрация worker и вычислительное ядро используют общие модели одного backend-проекта.

Контракт результата согласуется владельцами ядра и интеграции. JSON Schema 0.1 и пример получены для обсуждения, но ещё не утверждены и не импортированы. После согласования Python-модели и TypeScript-типы должны соответствовать единому контракту. Модель задания и HTTP-маршруты определяются отдельно, в NRT-13. Состояние задания не равно статусу сверки показателя.

Расчёт и выбор относящихся к договору/периоду документов выполняются в Python. UI показывает результат и адреса доказательств. Оригиналы и превью хранятся на диске; база хранит задания, метаданные и результаты. PostgreSQL получает постоянный volume; миграции версионируются.

Это целевая архитектура. В NRT-6 создана только структура; компоненты будут реализованы последующими задачами.

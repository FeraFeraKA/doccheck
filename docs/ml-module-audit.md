прочитана непосредственно в Linear 2026-11-13T00:02Z. Назначение `b1` запуска
`n90-20261112-2352` разрешает изучение, документацию и синтетические проверки;
исправления runtime в него не входят.

**Вывод:** код доступен и запускается без модели как обработчик готовых наблюдений.
Он не является полным конвейером OCR/КФЗ/финансовой сверки. Три замечания к PR #8
воспроизведены; реальный Qwen inference, качество, расход памяти и офлайн-развёртывание
не проверены. Этот аудит не является независимой предметной приёмкой или одобрением
модуля как готовой технической зависимости.

Python 3.14.4. Это характеристики устройства, **не минимальные требования модели**.
MLX, MLX-VLM, Transformers и Pillow в использованном окружении не устанавливались.
Веса и адаптер не предоставлены этому аудиту; чужие каталоги весов не исследовались.

В изолированном окружении внутри игнорируемого `data/nightly-state/` успешно

## Граница Python API

[DocumentInput и process_documents](../backend/ml_module/src/doccheck_ml/api.py)
получают **готовые наблюдения доверенного worker**, а не документ для автоматического
разбора и не клиентский HTTP JSON. Пример вызова есть в [README модуля](../backend/ml_module/README.md#вызов-из-worker).

| Вход | Проверяемый смысл |
| --- | --- |
| `id` | Непустая строка; ID документов в вызове уникальны. |
| `source_path` | `pathlib.Path` к сохранённому исходному файлу. Python API доверяет worker при выборе пути; ограничение каталога есть отдельно у CLI. |
| `source_sha256` | 64 строчных hex-символа, SHA исходных байтов на момент извлечения. При обработке вычисляется повторно. |
| `acquisition` | Только `native` или `scan`. Правдивость этой маркировки обеспечивает вызывающая сторона. |
| `lines` | Список словарей с `text`; допустимы `page`, `line`, `sheet`, `cell`, `bbox`, `score`, `image`. Нумерация страниц/строк с 1, bbox из четырёх упорядоченных конечных координат. |
| `prediction` | Необязательный словарь известных полей со строками или `null`: номер, дословная строка, договор, дата, период, сумма, категория, описание, цитата. |
| `synthetic` | Явный bool; по умолчанию `False`. Синтетические проверки передают `True`. |

SHA доказывает неизменность файла, но **не соответствие строк и prediction его
содержимому**. Входные пути, происхождение OCR, адреса и маркировку `native`
проверяет интеграционный worker. Координаты не переводятся автоматически в
нормализованный bbox общего контракта. Нельзя подавать независимый эталон.

Функция последовательно применяет identity v2 → v3 combined → v4 A2 → v5.
Она возвращает `records`, `groups`, `review_queue`, `errors`, версии, `synthetic`,
`status`, `inference_performed: false`, `financial_reconciliation_performed: false`.
В records есть предложения номера, `usable_value`, признаки ручной проверки,
`facts`, `source_facts`, адресуемые evidence и конфликты. `facts` может содержать
предложение модели без подтверждения в `source_facts`; смешивать их нельзя.
Деньги передаются строками, нормализация использует `Decimal`.

Неправильные типы/поля, повторяющиеся ID, неположительные номера страниц/строк
и некорректный bbox вызывают `InputError` до обработки. Семантика адресов ячеек
и листов не проверяется: например, `cell="A0"` и `sheet=""` принимаются.
Проверку существования и смысла адреса выполняет worker.
Недоступный файл даёт `source_unavailable`, изменённые байты —
`source_changed`; ошибочный документ исключается из records/groups, остальные
продолжают обрабатываться. При таких ошибках общий статус `partial`, иначе
`completed`. Пустой список также может завершиться `completed`: это статус прохода,
не полноты пакета. Группировка identity не удаляет файлы и не заменяет доказательство
дублей финансовых операций.

## CLI и форматы

[CLI](../backend/ml_module/src/doccheck_ml/cli.py) предоставляет:

```sh
doccheck-ml demo
doccheck-ml process --manifest /local/job/manifest.json --output /local/job/result.json
```

Манифест требует ровно `schema_version: "doccheck-ml-input/1"`, `synthetic` и
`documents`. Каждый документ содержит поля `DocumentInput`; `prediction`
необязателен. `source_path` относителен к каталогу манифеста: абсолютные пути,
выход через `..` и symlink за этот каталог отвергаются. Результат создаётся новым
файлом, существующий файл не перезаписывается. При корректно разобранных аргументах
коды выхода: 0 — обработка без ошибок файлов, 2 — частичная обработка,
1 — некорректный манифест/ошибка чтения или записи. Ошибка аргументов `argparse`
также возвращает 2 до обработки; один код 2 без результата не доказывает `partial`.
`process` печатает только счётчики; `demo` печатает полный **синтетический** результат.
Результат рабочего `process` содержит текст источников и хранится только локально.

`process_documents` проверяет байты файлов любого расширения, но **не разбирает**
PDF/DOCX/XLSX/PNG. Нужные строки предварительно извлекают другие компоненты.
`QwenReader` принимает один локальный PNG/JPEG-фрагмент; не полный PDF или таблицу.

## Qwen reader и готовые веса

API: `QwenReader(QwenConfig(model_dir=Path(...), adapter_path=...)).read(Path(...))`.
Импорт/конструктор модель не загружают. Первый `read` загружает локальные файлы,
дальнейшие используют кеш; один экземпляр предназначен для последовательного worker.
Изображение должно быть однокадровым PNG/JPEG, с расширением `.png`, `.jpg` или `.jpeg`.
Выделение фрагмента и привязку к исходному документу обеспечивает worker.

Нужны `config.json`, `model.safetensors`, `tokenizer.json`, `tokenizer_config.json`,
`processor_config.json`, `preprocessor_config.json`, `chat_template.jinja`.
Дополнительные `.safetensors` запрещены; опциональный индекс может ссылаться только
на `model.safetensors`. Для готового адаптера нужен `.safetensors` и соседний
`adapter_config.json`. `adapter_path=None` явно выбирает базу. Ошибка адаптера
не разрешает fallback; при восстановлении сверяются ключи, размеры и равенство
его тензоров. Загрузка адаптера не запускает тренировочный цикл.

Reader возвращает `prediction` с ровно `doc_number` и `verbatim_line` (строки/null),
хеши входа/весов/конфигураций/политики/запроса и `latency_s`. Это предложение,
не подтверждённый реквизит. `latency_s` начинается после загрузки модели,
поэтому не измеряет холодный запуск. Ошибки разделены на `QwenInputError`,
`QwenUnavailableError` и `QwenPredictionError` (в том числе обрезанный/невалидный ответ).

В README указан кандидат `mlx-community/Qwen3.5-4B-MLX-4bit`, revision
`32f3e8ecf65426fc3306969496342d504bfa13f3`. По текстовым
[карточке модели](https://huggingface.co/mlx-community/Qwen3.5-4B-MLX-4bit/resolve/32f3e8ecf65426fc3306969496342d504bfa13f3/README.md)
и [конфигурации этой ревизии](https://huggingface.co/mlx-community/Qwen3.5-4B-MLX-4bit/resolve/32f3e8ecf65426fc3306969496342d504bfa13f3/config.json):
база `Qwen/Qwen3.5-4B`, заявлена Apache-2.0, MLX SafeTensors, 4-bit affine,
group size 64. Около 2.9G на диске — заявление карточки, не замер RAM/VRAM.
Лицензия и качество конкретного локального адаптера не подтверждены.

Сам `QwenConfig` **не закрепляет** имя/revision модели: принимает локальный каталог.
Хеши вычисляются при первой загрузке, но не сравниваются с внешним доверенным
манифестом ожидаемой версии. После загрузки повторно не проверяются. До интеграции
нужно сверить разрешённую версию и SHA, затем обеспечить неизменность файлов.

Официальная [документация MLX](https://ml-explore.github.io/mlx/build/html/install.html)
описывает Apple silicon с macOS ≥14 и native Python ≥3.10, а также Linux CPU/CUDA
backends. Требование этого пакета Python ≥3.12 строже. Наличие backend не доказывает
совместимость данного reader, конверсии и контейнера: Linux/CUDA здесь не проверены.
Николай ожидает GPU для рабочего запуска; CPU smoke-test не подтверждает этот режим.

Лимиты политики 9 GiB памяти и 256 MiB кеша — настройки, не измеренные потребности.
Minimum/peak RAM и VRAM, холодная загрузка, latency и совместимость целевого GPU
остаются неизвестными. Код задаёт offline-флаги Hugging Face, `local_files_only=True`
и `trust_remote_code=False`; реальная сетевая изоляция не проверена. Ни веса,
ни optional runtime для этого аудита не скачивались, inference не выполнялся.

## Подтверждённые дефекты исходной версии

Все входы ниже созданы заново как синтетика. Проверки проходят через публичный API,
с настоящим временным файлом и его SHA, без модели и независимого эталона.

| Замечание PR #8 | Воспроизведение | Фактическое ограничение и требуемое исправление |
| --- | --- | --- |
| [Дата договора](https://github.com/VCyberPunk2077/doccheck/pull/8#discussion_r4557864144) | Заголовок `Акт № 17 по договору № CT-001 от 01.03.2026`, затем `Дата документа: 12.11.2026` | В `source_facts.date` остаётся `2026-03-01`. Нужна проверка роли даты и evidence самого документа. |
| [Неполный номер](https://github.com/VCyberPunk2077/doccheck/pull/8#discussion_r4557864155) | `Акт № 17...`, acquisition `native` | `usable_value="17"`, ручное ревью не требуется. Нельзя удалять признак неполноты до его проверки. |
| [Отрицательный итог](https://github.com/VCyberPunk2077/doccheck/pull/8#discussion_r4557864167) | `Итого: -100,00` либо соседние строки `Итого` / `-100,00` | Сумма не извлечена, `facts.amount=null`, в `source_facts` суммы нет. При prediction `100.00` положительное предложение сохраняется. Выделение токена должно сохранять знак и источник. |

В [test_nrt92_audit.py](../backend/tests/ml_module/test_nrt92_audit.py) пять
`expectedFailure`-тестов задают **желаемое корректное поведение** этих сценариев.
Они не объявляют дефекты нормой и не меняют runtime. После исправлений снять
соответствующие декораторы; unexpected success не должен быть проигнорирован.
До исправлений `completed` и пустая review queue не служат достаточным допуском
этих реквизитов к автоматической финансовой обработке.

## Фактически выполненные проверки

- Исходный набор: 161 тест — успешно на Python 3.14.4.
- После добавления аудита, установленный пакет: 166 тестов — 161 успешный,
  **5 ожидаемых падений** по трём незакрытым дефектам; других ошибок нет.
- `doccheck-ml demo`: 2 records, одна группа одинаковых байтов, `synthetic=true`,
  `completed`, оба признака inference/financial reconciliation — false.
- Установленный CLI `process`: корректный синтетический манифест — код 0;
  повторный выходной файл — 1; изменение исходных байтов после вычисления SHA — 2.
- Вызов reader без переданного каталога модели — `QwenUnavailableError`;
  это проверка честного отказа, а не настоящий inference.
- Существующие Qwen-тесты используют подменённый runtime. Они проверяют границу,
  но не загрузку реальных весов, качество, память или offline-работу.

## Границы интеграции и вопросы владельцу

Модуль уже выполняет нормализацию части реквизитов, identity-группировку и
формирование очереди ручной проверки. Парсинг исходных форматов, OCR страниц,
классификация комплекта, агрегация КФЗ, связь показателя с финансовыми первичными
документами, правила/допуски, итоговый `CheckResult`, API/БД/worker им не реализованы.
Низкоуровневые v3/v4/v5 умеют принимать доверенные повторные наблюдения, но публичный
`process_documents` не подключает их автоматически; успешное совпадение читателей
само по себе не является доказательством реквизита.

Семёну передаётся вопрос: какой **готовый разрешённый** комплект базы/адаптера
использовать (путь, revision/SHA, config, лицензия) и какое целевое GPU-окружение
подтверждено? Рекомендация — сначала зафиксировать этот комплект и измерить
inference/холодный запуск/peak memory/offline на разрешённой синтетике, без обучения.
Исправление трёх P2 требует отдельного назначения на runtime. Этот пробел не мешает
изучению интерфейса или независимому каркасу NRT-8; готовность ML-зависимых задач
координатор оценивает по их собственным критериям.

Данные: только созданные для аудита синтетические файлы. Реальные документы,
holdout, независимый эталон, секреты, веса и результаты настоящего inference
в Git/Linear/PR не добавлялись. Разрешённые примеры проекта не менялись.

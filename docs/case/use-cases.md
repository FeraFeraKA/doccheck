# Два сценария сверки на синтетическом комплекте

Ожидания ниже описывают синтетические пакеты и предназначены для проверки
поведения обработчика. Состав и хеши файлов проверены на срезе
`17f6a724ff4b447a344ad7f23cdbc1e49292e4eb`.

## Подготовка

Возьмите готовый [учебный комплект](../synthetic/nrt-89/README.md),
seed `890041`. В [списке входов](../synthetic/nrt-89/inputs.json) указаны пути,
роли и SHA-256 всех 23 файлов. Загрузите `inputs/01_kfz.pdf` как КФЗ, а файлы
с ролью `supporting` — как первичные документы. [Ожидания фикстуры](../synthetic/nrt-89/expectations/manifest.json)
открывайте отдельно при проверке результата. В приложение передаются только
файлы из списка. Независимые ответы организаторов остаются у владельца данных.

Учебная область — договор `SYN-00890041-КФ/47`, период 01.06.2036–31.10.2036,
этап 7. На странице 1 КФЗ проверяются строки таблицы «Суммы фактических затрат
за отчетный период, руб.» и строка «Итого» как контекст. Выбор файлов выполняется
в [локальном мастере](../../frontend/README.md#загрузка-и-история-проверок);
договор, период и адрес строки пользователь вручную не вводит.

При [штатном запуске Compose](../../README.md#запуск-каркаса-через-docker-compose)
можно проверить отправку, создание записи, статус `queued` и повторное
открытие карточки из истории. Следующие ожидаемые результаты предназначены
для приёмки после проверки сквозного пути на подходящем обработчике. Доступный
локальный адаптер v3.2 возвращает сформированные строки с `unverified` при
неизвестной полноте. Если в PDF КФЗ есть страница только с изображением, этот
адаптер завершает задание с `failed` и без результата: показания модели нужно
подтвердить по оригиналу. Оба сценария используют скан КФЗ из учебного
комплекта; по текущей реализации ожидаемые результаты с v3.2 недоступны.
Сквозные прогоны этих пакетов через адаптер не выполнялись.
[Локальный запуск и ограничения](../agent-runs/nrt-95-v32-local-windows.md).
Готовый результат в интерфейсе использует отдельный [пример контракта](../../contracts/check-result.v1.synthetic.json).

## 1. Загрузить весь опубликованный комплект

1. В мастере выберите КФЗ и все 22 первичных файла из списка. Отправьте пакет.
   При наличии рабочего адаптера дождитесь сохранённого результата и откройте
   «Сверка».
2. Сопоставьте результаты с манифестом. В учебном комплекте «Оплата труда»
   сходится на 986 204,37 руб., «Общепроизводственные расходы» — на 215 010,33 руб.
   Для «Страховых взносов» КФЗ содержит 297 880,85 руб., пять начислений
   из `03_insurance_06.xlsx`–`03_insurance_10.xlsx` дают 297 540,37 руб.
   Разница в строке — 340,48 руб. (`discrepancy`). Проследите её до строки
   взносов на странице 1 КФЗ и ячеек B6 листа «Расчет взносов».
   Строка взносов входит в «Итого» КФЗ. Общую подтверждённую сумму можно
   сравнивать с «Итого» только при достаточных доказательствах по всем
   входящим в него статьям.
3. В «Исключениях» сверьте причины по паре `09_admin_act.pdf` /
   `10_admin_copy.pdf` (байтовый дубль), `13_transfer.pdf` (другой договор)
   и `14_admin_act.pdf` (вне периода). На строке «Общехозяйственные расходы»
   227 070,15 руб. есть только как наблюдаемая сумма при неполных подтверждениях.
   У «Прочих расходов» подтверждающих файлов нет. В обеих строках ожидаются
   `unverified` и прочерки для полной суммы и дельты.
4. На вкладке «Документы» скачайте XLSX сохранённой проверки. Сверьте статус и
   дельту на листе «Сверка», адреса на листах «Слагаемые» и «Источники»,
   причины решений по файлам на листе «Документы».

В КФЗ этого набора приведён только факт. Для приёмки случая «факт ниже плана
и совпадает с КФЗ» владелец данных должен подтвердить отдельный синтетический вход с планом.
Ожидаемое поведение — сравнение КФЗ с подтверждённым фактом при достаточных
источниках. Разница с планом сама по себе не создаёт расхождение.


В учебном примере для «Оплаты труда» зададим план **1 000 000,00 руб.**
для того же договора и периода. План придуман для пояснения, отсутствует
во входных файлах и не извлекался. В КФЗ и подтверждающих ведомостях факт
равен **986 204,37 руб.** При полном основании ожидаются `verified`
и дельта **0,00 руб.**, поскольку обе фактические суммы совпадают. Это пример
ожидаемого поведения на подготовленных значениях. Продуктовая приёмка
и сквозной прогон с подтверждённым входом предстоят.

## 2. Заменить один акт повреждённым PDF

1. Возьмите тот же комплект. Замените только `inputs/04_act.pdf` производным
   `inputs/truncated_act.pdf` из сценария `truncated_pdf` в
   [генераторе повреждённых файлов](../../research/negative-fixtures/generate.py).
   Из корня рабочей копии запустите команду с `uv` и Python 3.12. Генератор
   создаёт все варианты за один запуск. Команда установит закреплённые
   версии `openpyxl`, `et-xmlfile` и Pillow во временное окружение.
   Выберите путь, которого ещё нет. Если `data/negative-fixtures-check` уже
   существует, укажите новый путь в `--output` и возьмите PDF из него.

   ```sh
   uv run --python 3.12 --no-project --with openpyxl==3.1.5 --with et-xmlfile==2.0.0 --with pillow==13.0.0 python research/negative-fixtures/generate.py --output data/negative-fixtures-check
   ```

   Для этого запуска берите только `data/negative-fixtures-check/inputs/truncated_act.pdf`.
   Состав остальных 22 файлов и параметры КФЗ сохраняются.
2. Ожидаемый результат при рабочем адаптере — отдельная ошибка чтения для
   повреждённого акта и `unverified` в «Общепроизводственных расходах».
   Строка КФЗ остаётся 215 010,33 руб. Три оставшихся подтверждения из
   `05_invoice_act.pdf`, `06_memo.docx` и `07_transfer.pdf` дают наблюдаемую
   сумму 138 633,62 руб. Полная ожидаемая сумма и дельта остаются `null`.
   Из строки перейдите к сведениям об ошибке и к сохранившимся источникам.
3. Скачайте XLSX на вкладке «Документы», если сохранён частичный результат.
   Сверьте наблюдаемую сумму и статус «Не проверен» (`unverified`) в «Сверке», ошибку в
   «Документах» и связанную причину в «Первичных замечаниях».
   Итоговое решение по обоим пакетам принимает бухгалтер. Экспорт служит
   отчётом о технической сверке и не требует автоматической подписи.

В этом срезе сверены 23 SHA-256, состав вариантов и арифметика по публичной
синтетике. Подключение подходящего обработчика и сквозной прогон обоих
сценариев остаются условиями продуктовой приёмки. Обработка этих пакетов, распознавание,
точные коды ошибок рабочих документов и вывод из оснований сверки
в этом срезе не проверялись.

# Локальный запуск обработки документов на Windows

Эта инструкция запускает интерфейс, API, PostgreSQL, отдельный worker и
локальную модель через скрипт `scripts/run-v32-local.ps1`. На Windows 11
ранее проверены два синтетических пакета с КФЗ XLSX и первичным DOCX.
Чистая установка требует отдельной проверки. Если PDF КФЗ содержит страницу
только в виде изображения, адаптер завершает задание с `failed` без
результата. Стандартный Docker Compose запускает другой, синтетический
worker; его порядок описан в [основном README](../README.md).

## Требования

- Windows с PowerShell 7 (`pwsh`).
- Git, Python 3.12, `uv`, npm и Node.js одной из поддерживаемых версий:
  `^22.22.2`, `^24.15.0` или `>=26.0.0`.
- Исполняемые файлы PostgreSQL 18, включая `initdb` и `pg_ctl`.
- Ollama и локальная модель `qwen3.5:4b-q4_K_M`. Адаптер проверяет не
  только имя, но и закреплённый в коде digest модели.
- Свободные локальные порты 15432 (PostgreSQL), 11438 (Ollama),
  8000 (API) и 8080 (интерфейс). Скрипт позволяет изменить порты БД, API
  и интерфейса; Ollama для v3.2 должна быть доступна на порту 11438.

При первой подготовке `uv`, npm и Ollama могут загружать зависимости и веса
из сети. Требования к оборудованию и полностью офлайн-установка пока не
измерены и не подтверждены.

## Подготовка модели

В отдельном терминале PowerShell запустите Ollama в локальном режиме:

```powershell
$env:OLLAMA_HOST = "127.0.0.1:11438"
$env:OLLAMA_NO_CLOUD = "1"
ollama serve
```

Если модель ещё не загружена, в другом терминале выполните:

```powershell
$env:OLLAMA_HOST = "127.0.0.1:11438"
ollama pull qwen3.5:4b-q4_K_M
```

Оставьте сервер Ollama работающим. Тег модели может со временем указывать
на другие веса. Если digest не совпадает с закреплённым в
[адаптере](../backend/src/doccheck_backend/v32_adapter.py), обработка
завершится с `v32_model_unavailable`; нужны проверенные веса нужной
версии, а не изменение проверки.

## Запуск

Из корня репозитория выполните команды по порядку. Для API, worker и сайта
используйте отдельные терминалы и оставьте их открытыми:

```powershell
pwsh -NoProfile -File scripts/run-v32-local.ps1 -Component database
```

```powershell
pwsh -NoProfile -File scripts/run-v32-local.ps1 -Component api
```

```powershell
pwsh -NoProfile -File scripts/run-v32-local.ps1 -Component worker
```

```powershell
pwsh -NoProfile -File scripts/run-v32-local.ps1 -Component site
```

Откройте [http://127.0.0.1:8080](http://127.0.0.1:8080). Для первого
прогона можно нажать «Загрузить пример»: мастер отправит синтетическую КФЗ
XLSX и первичный DOCX в рабочую очередь.

Адаптер принимает в роли КФЗ XLSX определённого шаблона или PDF с
адресуемыми реквизитами и суммами; не каждый файл этих форматов подходит.
Для XLSX нужен лист `КФЗ`: договор в A3, период и этап в A4, заголовки
«Статья затрат» в B6 и «Отчетная сумма, руб.» в C6. Порядок можно сверить
с [синтетической КФЗ](../frontend/public/demo/report.xlsx). Интерфейс также
позволяет выбрать другие форматы, но это не означает, что адаптер примет их
в роли КФЗ. Успешный запуск сервисов и синтетического примера сам по себе не
подтверждает правильность извлечения и сверки произвольных документов.

По умолчанию скрипт ищет PostgreSQL в `Program Files/PostgreSQL/18/bin`.
Для другого расположения передайте `-PostgresBin` командам `database`
и `stop-database`. При изменении `-DatabasePort` используйте одинаковое
значение для `database`, `api`, `worker` и `stop-database`; значение
`-ApiPort` должно совпадать у `api` и `site`.

Скрипт создаёт отдельный кластер PostgreSQL и локальный случайный пароль.
Кластер, пароль, загруженные файлы и результаты хранятся в
`data/v32-local-15432` при порте по умолчанию. Не добавляйте эти данные
в Git; подробнее — в [политике данных](data-policy.md).

## Остановка

Остановите API, worker, интерфейс и Ollama сочетанием Ctrl+C в их терминалах.
Затем из корня репозитория остановите PostgreSQL:

```powershell
pwsh -NoProfile -File scripts/run-v32-local.ps1 -Component stop-database
```

Каталог данных сохраняется для последующих запусков.

# Веб-загрузка DocCheck с локальным CUDA-worker

[NRT-108](https://linear.app/andreiakimov/issue/NRT-108/razvernut-demo-doccheck-na-vercel-i-render) · 14 ноября 2026

Vercel передаёт маршруты загрузки и чтения документов шлюзу Render. Шлюз отправляет HTTP через исходящее WebSocket-соединение Chisel на локальный API. API, PostgreSQL, каталог загрузок и worker с Qwen и LoRA работают в WSL. Внешний туннель принимает только один обратный порт на loopback Render и использует отдельный токен и проверку отпечатка ключа сервера.

Штатный мастер отправляет исходный multipart-пакет. Состояние, история, результат, источники и XLSX доступны только из исходного браузерного сеанса. Перед отправкой мастер получает cookie на 30 дней. Сеанс привязан к адресу сайта. Загрузка в Preview и в production создаёт разные сеансы. Локальный каталог и отдельная БД предназначены для веб-загрузок. Используйте синтетические документы для публичной проверки и соблюдайте правила проекта для рабочих комплектов. [Режим данных](../data-policy.md)

## Render

Создайте отдельный Web Service из `render-gateway.yaml` в ветке `nrt-108-render-local-worker`. Укажите этот файл в поле Blueprint Path. Проверка сервиса выполняется по `/health`. Маршруты загрузки при отключении ПК отвечают `503`.

Клиент Chisel 1.12.0 должен быть установлен в `~/doccheck-data/tools/chisel-1.12.0`. В WSL создайте секреты командой `bash scripts/doccheck-render-worker.sh credentials`. Передайте содержимое двух файлов в поля окружения нового сервиса Render через защищённый канал.

| Переменная Render | Локальный файл в `~/doccheck-data/render-uploads/` |
| --- | --- |
| `DOCCHECK_TUNNEL_TOKEN` | `tunnel-token` |
| `DOCCHECK_TUNNEL_SERVER_KEY` | `tunnel-server-key.base64` |

Запишите отпечаток из строки `Fingerprint` в логах запущенного Render. Ключ, токен и документы хранятся вне Git.

## Локальный API и туннель

Подготовьте отдельную базу `doccheck_render_uploads` с владельцем текущего пользователя WSL. API слушает `127.0.0.1:18083`. Скрипт применяет миграции при запуске. Для этого ПК укажите существующее CUDA-окружение `/home/datahunter/doccheck/.venv-ml`.

```bash
DOCCHECK_PILOT_VENV=/home/datahunter/doccheck/.venv-ml bash scripts/doccheck-render-worker.sh local
bash scripts/doccheck-render-worker.sh tunnel https://ИМЯ-СЕРВИСА.onrender.com ОТПЕЧАТОК
```

Запустите команды в отдельных процессах. Для остановки завершите процессы обычным SIGTERM. Локальный API и worker используют общий GPU lock с закрытым пилотом.

## Vercel

Сборка использует `frontend/vercel.mjs`. Укажите `DOCCHECK_RENDER_UPLOAD_ORIGIN` с HTTPS-адресом шлюза на Render без завершающего слеша. Существующий `DOCCHECK_RENDER_ORIGIN` задаёт маршрут отдельной страницы «Состояние системы». Для Preview используйте текущий проект Vercel и оставьте основной домен у предыдущего деплоя на время сквозной проверки.

1. Откройте `/checks/new` в Preview и загрузите синтетический комплект через мастер. Проверьте код `202` и переход к результату.
2. Дождитесь завершения, проверьте `versions.model_revision` с хешем LoRA, откройте источник и скачайте XLSX. В новом браузерном сеансе URL результата должен вернуть `404`.
3. После проверки направьте основной домен на проверенный деплой. Для отката назначьте предыдущий production deployment в Vercel.

## Проверки

- Локальный Chromium использовал production-сборку frontend, Nginx с конфигурацией шлюза и настоящий обратный туннель Chisel. Пакет из 23 синтетических файлов прошёл через мастер, очередь и RTX 2060. PostgreSQL сохранил `completed`, время от создания до сохранения результата 41,32 с. Сверены 23 SHA-256 исходников, 6 значений КФЗ с итогом и хеш адаптера LoRA в результате. Оригинал, фрагмент и XLSX получены. Чужой сеанс получил `404` на каждый из этих маршрутов.
- `437` тестов backend с PostgreSQL, `146` тестов frontend, сборка, lint, проверка маршрутизации двух режимов Vercel и статуса `503` при отключённом туннеле.
- Облачная проверка ожидает доступа к аккаунтам и публикации ветки. Можно начать с синтетического комплекта seed `890100`.

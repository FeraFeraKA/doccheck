# NRT-97 — чтение состояния, результатов и источников

[NRT-97 в Linear](https://linear.app/andreiakimov/issue/NRT-97/api-poluchat-sostoyanie-rezultat-i-istochniki-zadaniya)
и NRT-13 прочитаны 13 ноября 2026 года.

## Цель и критерии

Предоставить frontend согласованный доступ к состоянию сохранённого
задания, его результату и источникам.

- [ ] По ID возвращаются фактическое состояние, результат и ошибки.
  Состояние задания отделено от статусов показателей.
- [ ] Документы и адресные фрагменты относятся к указанному заданию.
  Произвольные пути к файлам не раскрываются.
- [ ] Для отсутствующего задания, неготового результата и недоступного
  источника возвращаются ошибки. Неизвестные значения не подменяются нулями.
- [ ] История запусков следует HTTP-контракту NRT-13.
- [ ] Автоматические проверки охватывают готовое и незавершённое задания,
  ошибки и границу доступа к файлам.

## Изменения

- История читается из PostgreSQL с непрозрачным курсором по дате и UUID.
  Прогресс в состоянии равен нулю для очереди и итогу для завершённого
  запуска. Для обработки и сбоя числовой прогресс пока недоступен.
- Результат и доказательства возвращаются из сохранённого
  `CheckResult`. Десятичные строки, `null`, пометка синтетики,
  файловые ошибки и адреса сохраняются.
- Оригинал принадлежит манифесту запуска. Путь строится только из
  серверных идентификаторов и проверяется перед потоковой выдачей.
  Фрагмент должен относиться к этому документу и доступному оригиналу.
- Просмотрены все 25 файлов разрешённого комплекта, включая сканы КФЗ
  и формы с адресами PDF, PNG, XLSX и DOCX. В тестах использована синтетика.

Рабочий адаптер относится к NRT-95. Скачивание XLSX результата относится
к NRT-36. Прогресс по отдельным файлам worker пока не сохраняет.

## Проверки

На Windows с Python 3.12.12 и отдельным PostgreSQL 18.4 прошли 149 тестов
`uv run --frozen pytest tests --ignore=tests/ml_module -q`. Из них 14
проверяют новые маршруты. Пройдены проверки курсора на совпадающих датах
и новой вставке между страницами, прогресса и ошибок задания, выдачи
оригинала и фрагмента, чужого ID, перенаправления каталога и недоступной БД.
Pytest сообщил известное предупреждение Starlette об использовании httpx.

Ruff check, Ruff format, `openapi-spec-validator`, `docker compose
config --quiet` и `git diff --check` прошли. База
`bb78a6d83f0fa3eb33b424751915559f1bde814c`. Контейнерный HTTP-прогон
и сквозной прогон с рабочим адаптером локально не выполнялись.

## Исправления по ревью PR #29

- Маршрут фрагмента с ID в пути принимает закодированные Unicode и
  точки внутри сегмента. Добавлен GET с query-параметром `evidence_id`
  для всех допустимых ID результата. Клиент может задать параметр через
  `URLSearchParams`, чтобы сохранить разделители и отдельные `.` или `..`.
  Схема CheckResult сохранена.
- Документ и оба маршрута фрагмента сверяют размер и SHA-256 открытого
  оригинала с манифестом. Скачивание использует этот же дескриптор после
  возврата в начало файла. Внешняя запись во время отдачи остаётся за
  пределами гарантии. Регрессия покрывает перезапись и замену файла того же
  размера обычным файлом.
- Прямой HTTP через Uvicorn и прокси Vite проверен на закодированных
  path ID и специальных query ID. Контейнерный nginx локально не запускался.
- На базе `be05a6a8175bc0e82c73c861318cd2d8e0e7e90c` прошли 152 backend-теста
  на PostgreSQL 18.4, Ruff, валидатор OpenAPI, проверка конфигурации Compose
  и diff check.
- Потоковый ответ закрывает открытый оригинал после завершения ASGI-вызова,
  включая ошибку чтения, обрыв соединения и отмену отправки. Все три сценария
  проверены через маршрут скачивания с подменой файла и ASGI-канала.

# NRT-43. Полный пакет из примеров кейса через браузер

[Задача NRT-43](https://linear.app/andreiakimov/issue/NRT-43/skvoznaya-integraciya-i-knopka-demo), проверено 14.11.2026. Тест вручную загружает оригинальный PDF КФЗ и 22 первичных документа через мастер. Он проверяет приём пакета, получение сохранённого результата, автоматическое определение области, частичную сумму с адресом доказательства, документированные исключения и экспорт XLSX. Отдельный сценарий исключает пять ведомостей оплаты труда и проверяет, что для этой статьи нет подтверждённой суммы, а остальные источники по-прежнему доступны.

Проверены оба README и все 23 разрешённых файла в `docs/case/examples/`. КФЗ, три акта PDF и один акт PNG содержат сканы, пять PDF содержат текст. У ведомостей и расчётов страховых взносов разные поля и листы. В двух DOCX суммы находятся в таблицах. Сверка байтов подтвердила повтор одного PDF. Из самих исходных документов видны примеры другого договора и документа за июнь. Тест проверяет конкретные причины исключения или ручной проверки. Он допускает неполноту и не использует закрытый эталон, фиксированные денежные итоги или предварительный манифест обработки.

В скане КФЗ указан договор 24/03/15-01. Строка по третьему этапу относится к 2026 году, а заголовок отчёта указывает на окончание этапа 30 мая. Тест ожидает пересечение этапа с календарным годом строки и проверяет, что первая страница открывается по адресу доказательства. Указанный в README кейса предел приёма документов по 31 мая требует отдельного решения. Политика приёма документов не выводится из этого скана.

Запустите локальные API, PostgreSQL, отдельный воркер с поддержкой PDF КФЗ и Ollama. Тест обращается к существующему приложению без подмены API. Из `frontend/`:

```powershell
pnpm install --frozen-lockfile
pnpm exec playwright install chromium --only-shell
$env:DOCCHECK_LIVE_URL = 'http://127.0.0.1:8080'
$env:DOCCHECK_LIVE_CASE = '1'
pnpm exec playwright test --config=playwright.live.config.ts v32-case.spec.ts --grep 'all 22'
```

Чтобы дополнительно проверить пакет без ведомостей, установите `DOCCHECK_LIVE_CASE_MISSING=1` и запустите тот же файл тестов с `--grep 'payroll omitted'`. Оба сценария выключены по умолчанию. Это отдельный тест от прогонов на двух сгенерированных XLSX/DOCX пакетах, которые меняют сумму и договор.

Тест сохраняет идентификатор задания для локальной диагностики. Текст источников, результаты сверки и снимки обезличенного пакета не включаются в отчёт. Успешная проверка подтверждает путь через браузер и свойства конкретного результата. Полная финансовая приёмка и кнопка запуска примера проверяются отдельно.

Подготовка проверена на Windows. Установка закреплённых зависимостей из кеша, TypeScript, lint и обнаружение тестов прошли. Прогоны с разрешёнными файлами будут выполняться после подключения версии воркера, поддерживающей PDF КФЗ.

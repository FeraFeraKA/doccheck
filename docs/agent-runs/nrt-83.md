# NRT-83 — перенос интерфейса Lovable

[Задача Linear](https://linear.app/andreiakimov/issue/NRT-83/proverit-i-vstroit-interfejs-lovable-v-frontend)
и комментарий Андрея прочитаны 13 ноября 2026 года.
[Источник](https://github.com/ananakimov/project-placeholder/tree/163f6367f91d9885b16685f0981290874858e955)
проверен на указанном коммите `163f636`. Следующий коммит источника относится к публикации.

Из источника взяты композиция и палитра рабочей области, боковая навигация,
двухшаговый выбор файлов, обзор и раскладка сверки с таблицей рядом с адресом
доказательства. Бухгалтеру доступны документы, исключения и заключение.
Маршруты используют существующий React Router. Стартовый экран
синтетического каркаса доступен по прежнему URL.

Исходник использует TanStack Start, React Query и компоненты Radix.
Его корневой маршрут подключает общие контексты ролей, проверок и действий
с проверкой. В исходных экранах есть подписи элементов выбора файлов и
навигации, готовые моки и зашитые ответы панели «Почему?». В DocCheck
мастер использует подписанные поля выбора КФЗ и первичных документов,
локальное состояние выбранных файлов и выбранного источника.

Для выбора примера используются имена из NRT-89, для результата — отдельная
фикстура NRT-86. Мастер описывает, что при рабочей сверке приложение собирает
сводные значения из первичных документов и сравнивает их с КФЗ. Синтетический
режим позволяет выбрать файлы локально и отдельно открыть готовый пример.
Над таблицей сразу видно число расхождений из результата проверки,
в том числе на узком экране. Статусы и дельты по отдельным показателям
доступны в таблице. Суммы форматируются из строк, отсутствие значения
показано прочерком. Источник
показывает структурный адрес из контракта. Для возможных причин предусмотрено
место под гипотезы, которые правила могут предложить на проверку бухгалтеру.
Фикстура не содержит таких гипотез. Vite и Docker получают два файла
синтетики из репозитория.

Рабочая обработка, сводка, оригиналы, экспорт и записи журналов требуют
интеграции. Формат отдельного сводного файла, подпись, исправления и
дашборд требуют решений команды. Следующий шаг — повторные ревью и
проверка GitHub Actions на актуальной базе.

## Проверки

- Node 26.12.1, pnpm 12.14.0. После обновления ветки на `main`
  `4360f397a9c2464b2c9b5b28acafe1d0c55ad69d` прошли
  `pnpm install --frozen-lockfile --offline`, `pnpm typecheck`,
  `pnpm test` (13 тестов), `pnpm build` и `git diff --check`.
- `pnpm test:e2e` — 6 сценариев на закреплённом Chromium. Проверены
  отсутствие переключателя ролей, выбор КФЗ и первичных документов,
  видимость расхождения, обозначение гипотез, ноль и отсутствующее
  значение, выбор адреса доказательства, доступность исключений после
  перезагрузки, выбор файла без secure-context API и отсутствие API-запросов
  в перенесённом интерфейсе. При 320×844 и 390×844 счётчик расхождений
  полностью виден при открытии результата без прокрутки. Два smoke-теста
  стартового каркаса используют моки API.
- Публичные экспорты среза, выбор файлов без secure-context API и
  проверка списка разрешённых файлов для Docker-контекста учтены после
  предыдущих ревью. Compose для актуальной версии локально не запускался.

## Постановка и критерии из Linear

### Уточнение постановки от 13 ноября 2026 года

- Один путь «Бухгалтер» для главного бухгалтера и его заместителей.
  Убрать переключатель и зависящие от роли ветви, обновить тесты.
- На входе КФЗ и первичные документы. Приложение собирает сводные
  значения и сравнивает их с КФЗ. На синтетическом экране обозначить
  демонстрационный характер результата.
- Показывать расхождения сразу. Возможные причины по правилам
  обозначать как гипотезы для проверки. Формат сводного файла, дашборд,
  подписание и кнопка исправления пока не утверждены.

### Цель

Проверить и встроить в текущий frontend код интерфейса, подготовленный Андреем в Lovable. Сохранить согласованный стек проекта, дизайн и существующую инфраструктуру.

### Готово, когда

- [ ] Получен исходный код и описано, какие экраны и элементы реально переданы; до получения кода выполнение этой части заблокировано.
- [ ] Выполнено ревью сгенерированного кода: зависимости, маршрутизация, состояние, доступность и соответствие правилам проекта; отличия от принятого стека и дизайна согласованы с Николаем.
- [ ] Подходящие элементы и необходимая структура встроены в текущий frontend на pnpm; React Router и существующая инфраструктура не заменены без решения владельца.
- [ ] Выполнены затронутые проверки, сборка и проверка интерфейса в браузере; непроверенные состояния и ограничения перечислены.
- [ ] Тестовые данные явно помечены, интеграция с настоящим backend не объявлена готовой.

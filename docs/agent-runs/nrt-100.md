# NRT-100 — клиент состояния и истории запусков

[NRT-100](https://linear.app/andreiakimov/issue/NRT-100/frontend-podklyuchit-status-zadaniya-i-istoriyu-zapuskov)
и [NRT-13](https://linear.app/andreiakimov/issue/NRT-13/kontrakt-api-i-moki-dlya-fronta)
прочитаны 13 ноября 2026 года. База работы `bb78a6d83f0fa3eb33b424751915559f1bde814c`.

- `frontend/src/pages/checks/runStatusApi.ts` читает `GET /api/v0/runs` и
  `GET /api/v0/runs/{run_id}` по OpenAPI. Клиент сохраняет порядок и непрозрачный
  курсор истории, запрашивает свежие данные и проверяет форму ответа. Тип
  состояния взят из `checkData.ts`. Счётчик `0`, неизвестный прогресс `null`
  и техническая ошибка остаются отдельными значениями.
- Опрос последовательно запрашивает `queued` и `processing` через 500 мс
  после ответа, завершается при `completed`, `completed_with_issues` или
  `failed` и возвращает последнее состояние. Ошибка запроса завершает опрос.
  `AbortSignal` отменяет запрос и ожидание. Тайм-аут запроса 5 секунд.
- `frontend/tests/unit/run-status-api.test.ts` подменяет `fetch`. Проверены
  пустая история и курсор, неверные ответы, переходы, все три финальных
  состояния, ошибки HTTP и сети, отмена при ожидании и поздний ответ.

На Node 26.12.1 и pnpm 12.14.0 прошли `pnpm install --frozen-lockfile`,
`pnpm lint`, `pnpm typecheck`, `pnpm test` (47 тестов) и `pnpm build`.
`git diff --check` прошёл.

После обновления на `be05a6a8175bc0e82c73c861318cd2d8e0e7e90c` клиент
проверяет отмену в `getRun` и `listRuns` непосредственно после ожидания

## Подключение после NRT-97

На базе `75e2bd481a51cb815ea3ef57f5619385336d5484` `ChecksOverview` получает
историю из API. Курсор страницы хранится в URL, поэтому перезагрузка
возвращает на ту же страницу. Поиск работает в пределах открытой страницы.
В списке видны ID, время создания и состояние. Готовый синтетический пример
открывается по прежней отдельной ссылке и обходится без запросов API.
`CheckDetail` читает ID из URL, отображает состояние, доступный прогресс и
техническую ошибку, прекращает опрос на конечном состоянии. Смена ID и уход
со страницы отменяют запрос. После сетевой ошибки запрос можно повторить.
`useCheckData` публикует промежуточные состояния для этого опроса.

- Прошли `pnpm lint`, `pnpm typecheck`, `pnpm test` (51 тест), `pnpm build`,
  `pnpm test:e2e` (9 сценариев Chromium с подменой API) и `git diff --check`.
- В отдельной PostgreSQL 18.4 применены миграции и создана тестовая запись
  с КФЗ и первичным документом. Chromium через Vite и настоящий Uvicorn
  загрузил список, повторил загрузку после перезагрузки, открыл запись из
  истории, восстановил её состояние по прямому URL. Через управляемые
  изменения строки PostgreSQL проверены `queued → processing → failed`,
  прогресс `0 из 2`, неизвестный прогресс, причина остановки и отсутствие
  новых запросов после конечного состояния. Зарегистрированы только GET
  истории и состояния. Тестовая БД удалена после прогона.

Рабочая загрузка относится к NRT-99, просмотры результата к NRT-101. В
браузерной проверке рабочий API читал тестовую запись, а её переходы
задавались в БД. Обработчик документов и ML в этом сценарии не запускались.

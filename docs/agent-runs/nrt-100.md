# NRT-100 — клиент состояния и истории запусков

[NRT-100](https://linear.app/andreiakimov/issue/NRT-100/frontend-podklyuchit-status-zadaniya-i-istoriyu-zapuskov)
и [NRT-13](https://linear.app/andreiakimov/issue/NRT-13/kontrakt-api-i-moki-dlya-fronta)
прочитаны 13 ноября 2026 года. База работы `bb78a6d83f0fa3eb33b424751915559f1bde814c`.

- `frontend/src/pages/checks/runStatusApi.ts` читает `GET /api/v0/runs` и
  `GET /api/v0/runs/{run_id}` по OpenAPI. Клиент сохраняет порядок и непрозрачный
  курсор истории, запрашивает свежие данные и проверяет форму ответа. Тип
  состояния взят из `checkData.ts`. Счётчик `0`, неизвестный прогресс `null`
  и техническая ошибка остаются отдельными значениями.
- Опрос последовательно запрашивает `queued` и `processing` через 500 мс
  после ответа, завершается при `completed`, `completed_with_issues` или
  `failed` и возвращает последнее состояние. Ошибка запроса завершает опрос.
  `AbortSignal` отменяет запрос и ожидание. Тайм-аут запроса 5 секунд.
- `frontend/tests/unit/run-status-api.test.ts` подменяет `fetch`. Проверены
  пустая история и курсор, неверные ответы, переходы, все три финальных
  состояния, ошибки HTTP и сети, отмена при ожидании и поздний ответ.

На Node 26.12.1 и pnpm 12.14.0 прошли `pnpm install --frozen-lockfile`,
`pnpm lint`, `pnpm typecheck`, `pnpm test` (47 тестов) и `pnpm build`.
`git diff --check` прошёл.

# Уточнение кейса и параллельная работа — 13.11.2026

Задачи: [NRT-15](https://linear.app/andreiakimov/issue/NRT-15/voprosy-organizatoram-i-konsultaciya-13-noyabrya)
и [NRT-106](https://linear.app/andreiakimov/issue/NRT-106/otdelnyj-flow-ispolnitel-i-nezavisimyj-revyuer-na-odnom-ustrojstve).
Поручение ограничено фиксацией переданного пересказа и обновлением режима;
полная предметная приёмка консультации и проверка двухчатового процесса остаются
отдельными частями задач.

- Добавлен `docs/case/README.md`: источник по памяти Андрея, актуальный сценарий,
  открытые вопросы и ссылка на исходное описание и критерии организаторов.
  Обновлены точки входа, архитектура и правила работы с кейсом.
- Описаны до трёх параллельных задач и до трёх независимых ревью, отдельные
  worktree внутри `doccheck/.worktrees/`, совместные ресурсы проверок,
  последовательное слияние и повторная проверка при изменении базы. Новый
  каталог исключён из Git; ночной протокол не изменён.
- В связанных задачах Linear уточнены сценарий и применимые критерии без смены
  статусов и ответственных. В открытых PR #23 и #24 обновлён контекст; PR #23
  ещё требует убрать переключатель ролей.
- `git diff --check` и проверка локальных Markdown-ссылок прошли. Две временные
  чистые worktree внутри `.worktrees/` созданы на одном коммите, их Git-индексы
  оказались раздельными; после проверки обе удалены без принудительной очистки.

Независимое предварительное ревью выявило общие порты и теги Docker-образов,
а также необходимость повторять ревью после устранения блокера. Инструкция
дополнена. При ревью PR уточнено, что распределитель общих ресурсов должен
быть единым для двух чатов; добавлены его роль и следующий шаг в этом отчёте.
Гонка обновления `main` во время GitHub merge не устраняется одной передачей head
SHA; пользователь выбрал последовательные слияния с обновлением веток, а
расхождение фактической базы проверяется и сообщается после merge.

Параллельные рабочие чаты, реальные PR-слияния, Docker и e2e-проверки этим
изменением не запускались. Форма сводного документа, необходимость отдельного
файла, применимость конкретной справки и правила округления остаются открытыми.

Следующий шаг: проверить актуальную версию PR независимым ревьюером и Codex
Code Review. После принятия документации по отдельному поручению испытать
двухчатовый режим на независимых задачах; вопросы по кейсу передать владельцам.

После HTTP 202 форма готова принять следующий комплект. До чтения записи из истории карточка показывает квитанцию. Рабочий список и очередь читают те же состояния, ошибки, даты и ссылки из API. В публичной сборке по-прежнему доступен отдельно помеченный готовый пример без запроса рабочей истории.

Для сохранённых результатов под итогом показано отдельное состояние задания. Колонка «Покрытие по сумме» показывает «—» для отсутствующих денежных данных и отдельно указывает число подтверждённых показателей, когда API возвращает счётчики. Число документов, договор, денежное покрытие и общие счётчики фильтров отсутствуют в DTO списка. Поиск по заголовкам и сортировка по названию охватывают текущую страницу. Фильтры по результатам выполняются на сервере до пагинации. Этапы OCR, процент обработки, архив и принятие требуют серверной поддержки. Загрузка остаётся ограниченной форматами действующего API.

Проверено: lint, typecheck, 146 Vitest, 39 Playwright, локальная и публичная сборки. Сопоставимые снимки очереди и списка сняты в Chromium 157 на 390, 768 и 1440 px. У DocCheck браузерный сценарий подменяет HTTP-ответы, проверяет HTTP 202, сброс формы, карточку реального статуса из DTO, переход в историю и фильтр. Запуск v3.2 в эти проверки оформления не входит.

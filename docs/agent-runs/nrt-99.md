# NRT-99 — загрузка КФЗ и первичных документов

[Задача Linear](https://linear.app/andreiakimov/issue/NRT-99/frontend-podklyuchit-zagruzku-dokumentov-i-sozdanie-zadaniya)
и контрактная задача NRT-13 прочитаны 13 ноября 2026 года.
База `ae17918e33baf2ab40ecd78c144b71310fe239ef` содержит экраны
NRT-84 загрузчик карточки NRT-100 и приём двух полей из PR #33.

## Цель и критерии Linear

Подключить подготовленный интерфейс Lovable к API создания задания.
Решение Николая от 13 ноября уточняет вход. В форме нужны КФЗ и
первичные документы. Область определяется внутри последующей обработки.

- [ ] Пользователь выбирает КФЗ и первичные документы. Состояние выбора
  и ошибки валидации понятны.
- [ ] Выбранные файлы передаются API создания задания. Полученный ID
  используется для перехода к карточке сохранённого задания.
- [ ] Ошибки сети и API отображаются без ложного сообщения об успешной
  обработке. Изменённый пакет отправляется с новым ключом.
- [ ] Отправка и обработка ошибок проверены автоматически. В интерфейсе
  рабочая отправка отделена от встроенного синтетического результата.

## Реализация

- `createRun.ts` формирует multipart с КФЗ в `report` и первичными
  документами в повторяемом `documents` в выбранном порядке. Клиент
  проверяет `202`, `queued`, ID и канонический путь статуса из
  заголовка `Location` на том же origin.
- `NewCheck.tsx` показывает выбор, ограничения форматов, числа и
  размера файлов, отправку и ошибки. На время запроса повторное
  действие заблокировано. После потери ответа повтор переиспользует
  снимок пакета и UUID. Изменение выбора сбрасывает подготовленную
  попытку. При уходе со страницы браузер отменяет чтение ответа.
- После подтверждения открывается `/checks/{run_id}`. Это карточка
  принятого задания, дальнейший статус загружается через NRT-100.
  Встроенный пример открывается по отдельной ссылке без POST.

## Проверки и границы

Node 26.12.1, pnpm 12.14.0. Прошли `pnpm lint`, `pnpm typecheck`,
`pnpm build`, 91 Vitest, 12 Playwright и `git diff --check`. Тесты
клиента и мастера покрывают multipart, переход, блокировку двойного
действия, сетевой сбой, структурированные ошибки, отмену и новый UUID
при изменении пакета.

Отдельный Chromium-прогон прошёл через Vite, FastAPI и PostgreSQL 18.4
с локальным хранилищем. Мастер отправил синтетические PDF КФЗ и XLSX
из разрешённого набора NRT-89 только в полях `report` и `documents`.
API вернул 202, браузер перешёл к карточке с состоянием «В очереди».
Повтор HTTP-запроса с теми же байтами и ключом вернул тот же ID, история
содержала ровно одну запись нового задания. Тестовый процесс обработки
не запускался. Фактическая обработка пакета зависит от NRT-95.

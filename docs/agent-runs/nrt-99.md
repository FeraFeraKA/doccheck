# NRT-99 — клиент загрузки пакета

[Задача Linear](https://linear.app/andreiakimov/issue/NRT-99/frontend-podklyuchit-zagruzku-dokumentov-i-sozdanie-zadaniya)
и контрактная задача NRT-13 прочитаны 13 ноября 2026 года. Клиент
подготовлен на базе `bb78a6d83f0fa3eb33b424751915559f1bde814c`, в которую
входят API приёма NRT-96 и экраны NRT-84.

## Цель и критерии Linear

Подключить подготовленный интерфейс Lovable к согласованному API создания
задания. Вход состоит из КФЗ и первичных документов. Параметры договора,
периода и адреса строки определяются по согласованному контракту.

- [ ] Пользователь выбирает КФЗ, первичные документы и согласованные
  параметры. Состояние выбора и ошибки валидации понятны.
- [ ] Выбранные файлы и параметры передаются API создания задания.
  Полученный ID используется дальнейшим сценарием.
- [ ] Ошибки сети и API отображаются без ложного сообщения об успешной
  обработке. Повторная отправка изменённых данных не выдаёт прежний результат.
- [ ] Значимая отправка и обработка ошибок проверены автоматическими
  тестами. В интерфейсе различимы тестовые и реальные данные.

## Готовый срез

`frontend/src/pages/checks/createRun.ts` формирует multipart по OpenAPI,
сохраняет порядок первичных документов и передаёт адрес строки КФЗ
как текстовый JSON. Браузер формирует границу multipart. Ответ проверяется
по HTTP 202, `queued`, допустимому ID и согласованному `Location` вида
`/api/v0/runs/{run_id}`, который возвращает NRT-96. Подтверждение означает
приём пакета в очередь. Клиент передаёт статус HTTP и доступные поля
ошибки API, включая индекс файла. Сетевые ошибки и отмена доходят
до вызывающего кода.

Одна подготовленная отправка хранит снимок файлов и параметров
с переданным UUID. Повтор той же функции отправляет тот же пакет
с тем же ключом. Следующую осознанную отправку нужно подготовить с новым UUID.
Клиент не повторяет запрос автоматически.

`NewCheck` уже хранит локальные файлы отдельно от записей примера.
Подключение формы и применение ключа по жизненному циклу этой формы
зависят от [решения о параметрах в NRT-13](https://linear.app/andreiakimov/issue/NRT-13/kontrakt-api-i-moki-dlya-fronta#comment-0041307d-969a-4511-9e4e-ca96f0638ca6).
Остаётся получить согласованные параметры, подключить клиент к форме,
показать отправку и ошибки и передать ID экрану состояния. Опрос и история
относятся к NRT-100.

## Проверки

Node 26.12.1, pnpm 12.14.0. Прошли `pnpm install --frozen-lockfile --offline`,
`pnpm lint`, `pnpm typecheck`, `pnpm build`, `pnpm test` и `git diff --check`.
Из 38 тестов 12 относятся к клиенту загрузки. Они проверяют сериализацию
multipart, ответ 202, ошибки, отмену, сохранение ключа и пакета при повторе.
В тестах используется синтетика и подмена `fetch`. Браузерный сценарий
рабочей отправки и проверка на живом API относятся к подключению формы.

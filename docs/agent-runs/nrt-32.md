# NRT-32 — техническая регрессия связей с доказательствами

[NRT-32](https://linear.app/andreiakimov/issue/NRT-32/sohranyat-istochnik-kazhdogo-znacheniya-pri-izvlechenii)
прочитана 14 ноября 2026 года. База `104b4e6cb1a5ab1bb6ab0ba6be47b11223043d8f`.
Проверяется существующий контракт сохранённого результата.

| Критерий задачи | Состояние в этом срезе |
| --- | --- |
| Каждое включённое слагаемое имеет адресное доказательство суммы и отдельные основания договора, периода и статьи, когда они нужны | Проверены ссылки и адреса двух слагаемых в синтетическом результате. Допуск документов в рабочей обработке относится к отдельным правилам. |
| PDF/PNG сохраняют правильную страницу, координаты и размер после OCR-преобразований | [Контракт](../result-source-contract.md#адреса-доказательств-и-допуск-суммы) описывает адрес и систему координат. Существующие тесты проверяют допустимость адреса; преобразования OCR и исходный размер в этом срезе не проверялись. |
| XLSX и DOCX имеют структурный адрес | XLSX проверен в связях нового сценария. Форматы адресов, включая DOCX, проверены существующими целевыми тестами. |
| Агрегирование сохраняет каждое слагаемое и его источник | Изменены суммы двух компонентов, перевёрнут порядок документов, evidence и компонентов. После JSON round-trip восстановлены раздельные исходные значения, ID, лист и ячейки сумм и реквизитов. Pydantic и Draft 2020-12 приняли изменённый результат. |
| ID однозначны внутри задания и не дают читать произвольные пути | Pydantic отклоняет повтор ID с другим адресом и ссылку на отсутствующее доказательство. HTTP-ограничения уже проверяются в NRT-97 и здесь не дублируются. |

`uv run --frozen pytest -q tests/test_evidence_provenance.py tests/test_result_contract.py`
дал 105 успешных тестов на Python 3.12.12. Ruff и `git diff --check`
прошли. Публичная синтетическая фикстура не менялась. Тест
проверяет контракт и сериализацию. Он не доказывает извлечение,
агрегирование или сохранение доказательств рабочим адаптером.

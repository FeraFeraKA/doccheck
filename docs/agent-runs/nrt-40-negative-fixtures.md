# NRT-40 — синтетические негативные файлы

[Задача NRT-40](https://linear.app/andreiakimov/issue/NRT-40/negativnye-fajly-i-scenarii-nepolnogo-komplekta) прочитана 14 ноября 2026 года. [NRT-71 и PR #35](https://github.com/VCyberPunk2077/doccheck/pull/35) описывают независимый аудит сценариев A01–A16. Здесь добавлены технические фикстуры для отдельных негативных входов.

Из корня репозитория с Python 3.11+. Генерация использует `openpyxl==3.1.5`
с `et-xmlfile==2.0.0` и `Pillow==13.0.0`. Для тестов нужен также
`pypdf==6.21.4`. Команда с `uv` создаёт временное окружение с зависимостями
генератора.

```sh
uv run --python 3.12 --no-project --with openpyxl==3.1.5 --with et-xmlfile==2.0.0 --with pillow==13.0.0 python research/negative-fixtures/generate.py --output data/nrt-40-qa
uv run --python 3.12 --no-project --with openpyxl==3.1.5 --with et-xmlfile==2.0.0 --with pillow==13.0.0 --with pypdf==6.21.4 python -m unittest discover -s research/negative-fixtures -v
```

Выберите новую директорию. В `inputs/` будут пять отдельных файлов для запуска по одному. `manifest.json` хранится рядом и содержит исходный путь, SHA-256 до и после, затронутую строку синтетической КФЗ, ожидаемый технический исход и влияние на полноту. Генератор берёт только перечисленные файлы из публичного NRT-89 и проверяет их по исходному манифесту. При генерации XLSX хеш конкретного результата фиксируется в манифесте, поскольку метаданные ZIP могут отличаться между запусками.

| Сценарий | Что проверяется |
| --- | --- |
| Обрезанный PDF | Сигнатура сохраняется, строгий PDF-ридер отклоняет содержимое. |
| Пустой файл | Ровно ноль байтов. HTTP 422 `invalid_input` уже покрыт в `backend/tests/test_run_upload.py`. |
| Отсутствующая вкладка ведомости | XLSX открывается, лист `Ведомость` удалён, вкладка с технической пометкой не содержит зарплатных данных. |
| Поворот PNG | Пиксели повёрнуты на 90° против часовой стрелки, ширина и высота меняются местами. |
| Шум PNG | Чёрные и белые точки воспроизводятся при seed `890041`, вероятность замены пикселя 3%. Размеры сохраняются. |
| Совпадающая частичная сумма | Манифест ссылается на существующую строку NRT-89. Её наблюдаемая сумма равна заявленной, покрытие остаётся неполным, статус `unverified`, подтверждённая сумма и дельта равны `null`. |

Проверки фикстур охватывают происхождение, неизменность входов, структуру производных и ссылку на ожидание NRT-89. Привязка дефекта к реальному показателю, критерии обязательности ведомости, OCR и продуктовая приёмка остаются открытыми.

На исходной базе `71827ee` пять тестов NRT-40 прошли. Два из семи тестов NRT-89 на Windows останавливались при сравнении `A3`: верификатор читал UTF-8-манифест в системной кодировке. [PR #60](https://github.com/VCyberPunk2077/doccheck/pull/60) исправил чтение отдельно, без изменения исходных файлов. На базе `f2781e1` повторены пять NRT-40 и семь NRT-89 с `PYTHONUTF8=0`, все прошли. CLI, Ruff и `git diff --check` также прошли.

Оба PNG-варианта используют `12_communication.png` из учебного набора,
относящийся к `general_admin`. Манифест фиксирует размеры, режим и SHA-256
декодированных пикселей вдобавок к SHA-256 каждого сохранённого файла.
Оба PNG декодируются. Влияние на рабочее извлечение, ошибки обработки и
полноту статьи нужно проверить отдельным прогоном.

На базе `17f6a72` с Pillow 13.0.0 прошли шесть тестов NRT-40, семь NRT-89
в Windows с отключённым режимом UTF-8, отдельный запуск CLI, Ruff и
`git diff --check`. Повторная генерация PNG дала те же пиксели,
исходные файлы не изменились.

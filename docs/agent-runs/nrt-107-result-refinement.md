# NRT-107 Экран результата

Основание — промпт №3 от 14.11.2026 и [NRT-107](https://linear.app/andreiakimov/issue/NRT-107/sinhronizirovat-izmeneniya-interfejsa-andreya-s-doccheck).
Часть изменений уже в main через PR #81: список без карточек, отсутствие
черновиков и действий по строкам, блок недостаточных подтверждений.

Сводка, таблица, дополнительные проверки и заключение разделены по
последовательности работы бухгалтера. Ссылки открывают документы и
сохраняют адреса доказательств. Распределение по сумме вычисляется в
Python из известных значений КФЗ. Дельта остаётся отдельным показателем.
Для денежной сводки требуются явные признаки итоговых строк. Если старый
результат не даёт нужного основания или несколько статей ссылаются на
один адрес, денежная сводка недоступна, но статусы и детали видны.

Контракт результата дополняют необязательные поля `report_number`,
`is_aggregate` и `summary.rub_coverage`. Миграция не требуется.
Номер КФЗ должен поступать от адаптера из установленного реквизита.

Локально прошли lint, typecheck, 146 Vitest, 38 Playwright (включая
320, 390, 768 и 1440 px), обе сборки, 355 backend-тестов. Ещё 51 backend-тест
требует PostgreSQL. Проверка OpenAPI прошла. Браузерные сценарии используют
синтетические данные и подмену транспорта API.

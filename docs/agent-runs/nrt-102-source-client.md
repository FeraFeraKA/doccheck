# NRT-102 — клиент источников проверки

[Задача NRT-102 в Linear](https://linear.app/andreiakimov/issue/NRT-102/frontend-podklyuchit-prosmotr-istochnikov-pokazatelya)
прочитана 13 ноября 2026 года. База `75e2bd481a51cb815ea3ef57f5619385336d5484`
содержит HTTP API источников из NRT-97.

## Область

Этот срез готовит клиент для подключения к просмотру источников. Компоненты
экрана, форматирование адресов и клиент результатов NRT-101 не затронуты.
Для полного выполнения NRT-102 ещё нужно подключить выбор доказательства и
документа к UI, показать адрес или состояние его недоступности, провести
браузерный прогон и подтвердить работу с результатом адаптера NRT-95.

## Изменения

- `getSourceOriginal` читает байты оригинала как `Blob`, проверяет
  media type ответа и отличает пустое тело от загруженного файла.
- `getSourceEvidence` использует query `evidence_id` через
  `URLSearchParams`. Поддерживаются Unicode, разделители и составные ID.
  Run ID и document ID проверяются как сегменты по OpenAPI.
- Ответ Evidence проверяется по используемым полям контракта.
  Клиент сверяет оба идентификатора и принимает адрес страницы, листа,
  абзаца или ячейки таблицы. Десятичные значения сохраняются строками,
  отсутствующие границы периода остаются `null`.
- HTTP-ошибка содержит статус и распознанный код из контракта.
  Сетевые ошибки, отмена запроса и некорректный ответ различаются.
  Отмена проверяется и после чтения тела ответа. Успешный ответ обоих
  маршрутов требует HTTP 200. Частичный ответ HTTP 206 отклоняется.

## Проверки

На Node и pnpm проекта прошли установка `pnpm install --frozen-lockfile
--offline`, `pnpm lint`, `pnpm typecheck`, `pnpm build`, `pnpm test`
и `git diff --check`. Vitest прошёл 58 тестов, включая 32 проверки нового
клиента на синтетических HTTP-ответах. БД, настоящий worker и браузерный
сценарий с подключённым клиентом не запускались.

## Компонент просмотра источника

На базе `208fdf7df8387cb5b5127ec0ac8f05c41527c7bf` добавлен
`DocumentSourcePreview`. Все 25 разрешённых примеров, включая оба README,
КФЗ, сканы, таблицы и DOCX, просмотрены при проверке форматов адреса.
Браузерные и компонентные тесты используют синтетические данные.

Компонент принимает `runId`, выбранный `document` с полями `id`, `name`
и `format`, а также `evidenceId`. Встраивание на экране может передать эти
поля из выбранного документа и доказательства. Для отсутствующего документа
или доказательства передаётся `null`. Компонент экспортирован из среза
`pages/checks`. Маршруты и данные экрана остались в ведении NRT-101.

- PDF открывается в просмотрщике браузера на странице из адреса. Текстовый
  адрес включает строку, ячейку или идентификатор фрагмента, когда они
  доступны. Рамка внутри PDF в этом срезе отсутствует.
- PNG отображается с рамкой при наличии нормализованного `bbox` на
  первой странице.
- XLSX и DOCX доступны как оригинал для скачивания и адрес в интерфейсе.
  Встроенной отрисовки содержимого нет.
- Отсутствующий адрес и недоступный оригинал показываются отдельно.
  При смене выбора, повторе и размонтировании запросы отменяются, а Blob URL
  освобождается. Устаревший ответ не заменяет текущий источник.

Прошли lint, typecheck, build, 92 теста Vitest, включая девять новых
компонентных сценариев, и diff check. Отдельный Chromium-прогон на Vite
порту 55702 проверил PDF-ссылку с номером страницы и передачу ID,
отрисовку PNG с рамкой, адреса и скачивание XLSX/DOCX, а также доступность
оригинала при отсутствии фрагмента. PDF-плагин и офисное приложение в
этом прогоне не открывались. Работа с настоящим результатом зависит от
подключения адаптера NRT-95.

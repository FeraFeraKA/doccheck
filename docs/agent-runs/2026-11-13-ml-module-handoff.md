связанная граница — [NRT-93](https://linear.app/andreiakimov/issue/NRT-93/soglasovat-interfejs-ml-modulya-i-rezultat-obrabotki).

передать модуль в GitHub до завершения обучения. Основа ветки — `origin/main`,
`cd83466`; существующие рабочие копии и файлы обучения не изменялись.

## Изменения

- `backend/ml_module`: устанавливаемый пакет 0.1.0, Python/CLI для наблюдений,
  существующая identity-политика v2–v5 и отдельный локальный Qwen/LoRA reader.
- `backend/tests/ml_module`: только автономные синтетические проверки.
- `.github/workflows/ml-module.yml`: CPU-проверки без модели; `.gitignore`
  исключает веса safetensors/GGUF.
- README корня/backend ссылаются на инструкцию установки и границы модуля.

Исходные функции правил перенесены из локального `bench` с относительными
импортами и аннотациями. AST-сравнение подтвердило сохранение тел политик
v2/v3/v5, парсеров денег/дат и чистых функций исправления источников. В v4
единственная функциональная адаптация — явные `source_observation` вместо
чтения OCR-кэша по пути. Коррекция суммы без этих наблюдений пропускается.
Порог 80 и защита от новых автоматических объединений сохранены.

## Ограничения и следующий шаг

Передан код реквизитов и чтения номера, а не полный финансовый `CheckResult`.
API, worker, форматные парсеры, OCR-движки, обработка КФЗ и общий интеграционный
контракт не объявляются реализованными. Синтетический результат не является
проверкой разрешённого исходного комплекта или независимой приёмкой.

Реальные веса/адаптер не загружались и не публиковались. Загрузчик проверен
на подменённом runtime. Качество, скорость, минимальные GPU/RAM, контейнер и
Linux/CUDA остаются непроверенными; 9 GiB — настройка ограничения MLX. После
обучения нужно передать выбранный checkpoint и конфигурацию отдельно, зафиксировать
их SHA и выполнить фактические проверки в целевом окружении. NRT-55, NRT-92 и
NRT-93 не помечаются завершёнными; человеческая приёмка ещё предстоит.

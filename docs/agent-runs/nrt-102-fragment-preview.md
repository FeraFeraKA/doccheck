# NRT-102 — текстовый просмотр адресного источника

[Задача в Linear](https://linear.app/andreiakimov/issue/NRT-102/frontend-podklyuchit-prosmotr-istochnikov-pokazatelya),
прочитана 14.11.2026. Сценарий открывает документ и фрагмент, на котором
основано доказательство. Неподтверждённый адрес, неподдержанный формат,
недоступность оригинала и ошибка загрузки должны оставаться различимы.
Поддержка PDF, изображений, XLSX и DOCX ограничена полученными адресами.
Проверка в браузере с реальным сохранённым результатом относится к UI.

## Интерфейс

`GET /api/v0/runs/{run_id}/documents/{document_id}/fragment-preview?evidence_id=...`
возвращает `{"text": string|null, "highlight": {"start_byte": integer, "end_byte": integer}|null}`.
Эндпоинт принимает только сохранённый ID доказательства. Текст получен из
открытого оригинала с подтверждённым SHA-256. Ответ не кешируется.

В UI для подсветки следует кодировать строку через `TextEncoder`, выделить
диапазоны `[0, start_byte)`, `[start_byte, end_byte)` и `[end_byte, length)`
в байтах и декодировать каждый через `TextDecoder`. Индексы нельзя передавать
напрямую в JavaScript `String.slice`, поскольку строковые позиции UTF-16
отличаются от позиций байтов UTF-8. Для запроса применяйте
`new URLSearchParams({evidence_id: id})`.

При `text=null` клиент может показать сохранённый адрес и дать скачать
оригинал. При `highlight=null` отображается сам текст без выделения. Причины
включают неоднозначное буквальное совпадение, отсутствие точного адреса
нативного текста, неподдержанный формат или пределы размера. PNG остаётся
доступным по сохранённому адресу с bbox через существующий `GET /fragments`.
Адреса PDF без сохранённого bbox или идентификатора нативного фрагмента
не разворачиваются в текст.

Для денежного доказательства подсветка сверяется с полным исходным числом
и сохранённым точным значением. Если совпадает только целая часть суммы,
пропущен знак или после суммы отдельно записаны копейки, частичный диапазон
не выдаётся. Текст источника остаётся доступен.

## Границы

Поддерживаются адрес абзаца или ячейки DOCX, одиночная ячейка XLSX и точный
фрагмент нативного текста PDF. Максимальный объём оригинала 8 МиБ, суммарный
развёрнутый размер OOXML 32 МиБ, ответ содержит до 4096 байт UTF-8.
Существующие `GET /fragments` и скачивание сохраняют отдельно свои форматы.
Обработка выполняется локально. Публичный режим блокирует получение
превью до чтения оригинала.

При сверке адресов просмотрены все файлы в папке примеров кейса.
Примеры DOCX дают адреса абзацев и табличных ячеек, XLSX — ячеек листов.
Расчётный КФЗ в PDF и несколько первичных PDF не содержат видимого
нативного текста в пределах используемого парсера. Их изображения нельзя
превращать в текстовый фрагмент из сохранённых реквизитов.

Проверки: 102 теста с отдельным PostgreSQL подтвердили принадлежность
доказательства, сравнение контрольной суммы, отказ для изменённого файла,
UTF-8 с кириллицей и emoji, несколько форматов и запрет в публичном режиме.
Ruff, форматирование и проверка OpenAPI прошли.

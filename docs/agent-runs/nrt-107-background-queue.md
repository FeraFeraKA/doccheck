# NRT-107 Очередь и история

Промпт №3 от 14.11.2026 и [NRT-107](https://linear.app/andreiakimov/issue/NRT-107/sinhronizirovat-izmeneniya-interfejsa-andreya-s-doccheck).
После подтверждённого HTTP 202 форма очищается и готова к следующей
отправке. До обновления истории показывается квитанция об успешном приёме.
Оба списка читают одну очередь PostgreSQL и обновляются при открытой
странице. При сетевой ошибке история показывает последний полученный список
и сообщает о сбое. Повтор неизменённого пакета использует тот же ключ.
В публичном режиме история и отправка отключены.

Фильтр `finding` применяется перед курсором и извлекает счётчики из
сохранённой сводки. Ошибка worker остаётся состоянием задания. Статус
`processing` показывает обработку документов с неопределённой
длительностью, отдельный этап сверки пока не сообщается. Compose перезапускает
документный worker при аварийном выходе, новый владелец очереди помечает
прерванные задания через существующий механизм.
Архив требует серверного хранения принятия. Рабочий процессор нужно настроить
и проверить отдельно по NRT-95 и NRT-43.

Проверки: lint, typecheck, 146 Vitest, 39 Playwright, обычная и публичная сборки,
Ruff и валидация OpenAPI. В браузерном тесте два набора отправлены через
подменённый HTTP API, история восстановилась после перезагрузки. Новая
интеграционная проверка фильтров требует PostgreSQL в CI. Миграций и новых
зависимостей нет.

Квитанция удаляется после первого появления запуска в серверной истории.
Поэтому более новые задания не возвращают устаревшие квитанции на первую
страницу. Номер КФЗ в списке зависит от необязательного реквизита
`report_number` из PR №82. На старых результатах остаётся ID запуска.

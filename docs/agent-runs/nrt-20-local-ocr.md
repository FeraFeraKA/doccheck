# NRT-20 — локальный адресный OCR в воркере

[NRT-20](https://linear.app/andreiakimov/issue/NRT-20/ocr-dlya-skanov-i-png)
требует OCR в разрешённой локальной среде, источник каждого значения, проверку
координат и отказ от уверенной суммы при недостаточных данных. Интеграция
переиспользует PP-OCRv5 с заранее подготовленными локальными весами.

Укажите `DOCCHECK_OCR_PROVIDER=doccheck_backend.local_ocr:read_paddle`,
`DOCCHECK_PADDLE_DET_DIR` и `DOCCHECK_PADDLE_REC_DIR` в окружении воркера.
Два последних пути ведут к готовым каталогам моделей. Адаптер использует
настроенный провайдер только для сохранённых PDF и PNG. При отсутствии
провайдера и текстового слоя сохраняется `v32_pdf_scope_unavailable`.

Слой провайдера возвращает `NativeDocument` с `Observation`: текст,
`PageLocator` с номером страницы и нормализованным bbox, уверенность
в диапазоне 0–1. Провайдер обязан указывать рамки в системе исходной
страницы, которую открывает UI. В Paddle-варианте выключены изменение
ориентации и выпрямление изображений. Размеры проверяются при
преобразовании пиксельных рамок. Отклонённые рамки дают диагностику
без текста или путей исходных документов.

Адаптер выбирает однозначную годовую строку по номеру этапа и году
подтверждённой даты окончания. Период заканчивается датой из КФЗ.
Неоднозначная строка или отсутствующая область завершает задание с
ошибкой. Неподтверждённая денежная колонка получает явный непроверенный
статус и пустую сумму. В скане первички адресованные реквизиты могут
помочь ручной проверке; модельная цитата сама по себе не доказывает
финансовое слагаемое. Нативные суммы и адреса по прежнему контракту
сохраняются.

Проверки: `uv run --project backend --frozen pytest -q
backend/tests/test_local_ocr.py backend/tests/test_v32_adapter.py`.
Проверены выбор строки и границ этапа, неоднозначные строки, привязка
рамок и интеграция в CheckResult с тестовым провайдером. Живой запуск
с подготовленным офлайн окружением проверяет координатор отдельно.

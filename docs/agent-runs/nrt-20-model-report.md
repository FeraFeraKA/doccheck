# NRT-20 — чтение КФЗ локальной моделью

[NRT-20](https://linear.app/andreiakimov/issue/NRT-20/ocr-dlya-skanov-i-png)
и [NRT-95](https://linear.app/andreiakimov/issue/NRT-95/podklyuchit-ml-adapter-k-worker-i-sohraneniyu-rezultata)
прочитаны 14.11.2026. По уточнению Николая читаемые страницы приходят
в модель как текст, растровые — как изображения. Существующий
маршрут готовой Qwen в локальной Ollama используется без стороннего OCR.

- `v32_report_model.py` собирает запрос к Qwen по страницам. Адресуемый PDF
  передаётся текстом, смешанный PDF сохраняет порядок страниц, а разрешённый
  XLSX передаётся с текстом двух ячеек реквизитов листа КФЗ. В запросе нет фиксированных номера этапа,
  года и сумм.
- `v32_adapter.py` сопоставляет предложенные моделью договор и период
  с нативно прочитанными реквизитами. При расхождении или отсутствии ответа
  сохраняет исходные нативные доказательства и сообщает о расхождении в сводке.
- Скан без независимо адресуемой области выдаёт ошибку проверки с отдельной
  причиной для предварительного ответа и для отсутствия чтения. Реквизиты и
  суммы из модельного ответа не выдаются за подтверждённые, поскольку ответ
  текущей модели не содержит проверяемой привязки к строке и колонкам КФЗ.
- `test_v32_adapter.py` проверяет тип реальных входных данных и безопасный
  результат для читаемого XLSX и PDF, полного и смешанного скана.

Проверены 23 входных файла и два README разрешённого комплекта. В официальном
КФЗ одна страница без текстового слоя. Локальный вызов штатного worker adapter
получил от закреплённой Qwen завершённый ответ на одно изображение КФЗ
за 2,58 с. Задание завершилось с
`v32_pdf_scan_scope_unconfirmed` и отсутствующим результатом. Этот прогон
подтверждает передачу изображения, версию stock Qwen и безопасную обработку
предварительных реквизитов. Отдельный артефакт LoRA Семёна и его контракт
структурированного адресного результата ещё нужно подтвердить.

В worktree с общим обработчиком страниц прошли 34 проверки
`uv run --project backend --locked --with-requirements bench/e2e_v32_20261114/requirements.txt pytest backend/tests/test_v32_adapter.py -q`,
Ruff по изменённым Python-файлам и `git diff --check`. Вместе с тестами
`backend/tests/test_run_worker.py` на отдельной PostgreSQL прошли 56 проверок.
База и HTTP API сохраняют обе причины ошибки и подставляют сообщения сервера.
Свободный текст адаптера игнорируется, для неизвестных кодов действует
общее сообщение об ошибке.

## Постановка и критерии Linear

Цель NRT-20 — локально распознавать сканированную КФЗ, первичные PDF и PNG.
По уточнению владельца от 14.11.2026 backend передаёт модели нативный текст
читаемых страниц и изображения растровых страниц. Готовая модель
используется для вывода, её веса не меняются. Отдельные Windows OCR и
PaddleOCR не входят в согласованный путь. Критерии NRT-20:

- Целевая строка КФЗ связана с кодами статей и многоуровневой шапкой. У
  каждого прочитанного значения есть источник.
- Скан КФЗ, первичные сканы 04, 08, 15 и PNG 12 проходят распознавание в
  разрешённой локальной среде.
- Сохраняются распознанный текст, bbox, размер изображения, номер страницы,
  версия модели и доступная оценка качества.
- Поворот и масштабирование сохраняют точную обратную проекцию рамки на
  оригинал.
- Неуверенные суммы и неподдерживаемая форма дают `unverified`.
  Независимый эталон не используется для исправления распознавания.
- Подготовленные веса и языки доступны заранее. Обработка не требует
  внешнего API или загрузки весов.

NRT-95 требует, чтобы отдельный worker получал КФЗ и первичку, сохранял
сводные значения с проверяемыми источниками и отделял ошибки файлов и
обработки от выводов сверки. Данный срез проверяет условия передачи и
обработку неподтверждённого ответа. Приёмка всей сквозной сверки скана КФЗ
ожидает проверенного адресного контракта модели. При отсутствии достоверной
области результат не создаётся, API возвращает конкретную причину.

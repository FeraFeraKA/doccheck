При обычной загрузке форма «Указать строку КФЗ» отсутствует. Ручной ввод доступен по ссылке на экране неудачной проверки скана. Старый запуск без подтверждённого номера показывает имя файла КФЗ. Растровый номер сохраняется, если чтение заголовка совпало с чтением отдельного фрагмента. Для старых результатов без признаков аддитивности денежное покрытие может быть недоступно.

Браузер отправляет байты только новых файлов. Сервер переносит неизменённые оригиналы с проверкой SHA-256. Процессоры создают доказательства для нового запуска и сверяют весь изменённый комплект. Между запусками нет переиспользования извлечённых наблюдений: прежний v3.2 использует временный каталог, а текущий процессор повторно вызывает чтение документов. PostgreSQL-тест подтвердил новую запись и неизменность исходной. В двух запусках одинакового тестового XLSX и DOCX с подменой Ollama прежний адаптер сделал по два вызова модели. Ускорение обработки за счёт кеширования остаётся отдельной работой.

На объединённой базе прошли 147 Vitest, 73 Playwright, проверка типов, сборка, Ruff и OpenAPI. Прогон затронутых backend-тестов с отдельным PostgreSQL дал 178 успешных и два пропуска растровых тестов из-за отсутствия локального Tesseract. Совпадение OCR заголовка и фрагмента покрыто тестом с подменой чтений. На локальном API с реальной Ollama прошли две тестовые загрузки v3.2. Отдельный тестовый XLSX подтвердил прохождение номера КФЗ от заголовка до результата и истории, действительный XLSX-файл и «Принят» после нового запроса архива.

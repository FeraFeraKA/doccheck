# NRT-96 — приём пакета для проверки

[Задача Linear](https://linear.app/andreiakimov/issue/NRT-96/api-prinyat-dokumenty-i-sozdat-zadanie-proverki)
прочитана 13 ноября 2026 года. Основа — HTTP-контракт из PR #22.

`POST /api/v0/runs` проверяет multipart, число и размеры файлов, формат и
параметры области. Сохраняет байты под серверными ID, ставит задание в
PostgreSQL и отвечает 202. Неподтверждённый сбой записи не оставляет запись
очереди. Уникальный ключ и отпечаток запроса защищают от повторов.
При неопределённом результате коммита файлы сохраняются, чтобы не потерять
данные уже принятого задания. Возможный каталог без записи БД остаётся
вне очереди. Compose использует постоянный том для оригиналов.

Проверки на синтетике: 114 тестов backend с локальным PostgreSQL,
включая два одновременных запроса с одним ключом, конфликт, неверный ввод,
предел размера и повтор после сбоя записи. Ruff check, Ruff format check,
`docker compose config --quiet` и `git diff --check` прошли. Локальный Docker
daemon недоступен. Статус задания, выдача оригиналов и реальная обработка
относятся к следующим задачам. Ответ 202 означает, что пакет сохранён.

По независимому ревью превышение количества частей multipart возвращает
`422 invalid_input` даже при ранней остановке парсера. Проверены пакеты
со 101 и 102 первичными документами. Повторный прогон с PostgreSQL — 116 тестов.

После Codex Code Review повреждённое имя записи OOXML сохраняется для
пофайловой ошибки. На Windows файлы синхронизируются без POSIX-вызова для
каталога. Нативный Windows-прогон не проводился. С PostgreSQL прошли 117 тестов.

## Повторная проверка 13 ноября 2026 года

Актуальная задача Linear подтверждает вход из КФЗ и первичных документов.
Номер договора, период и адрес строки передаются согласно HTTP-контракту
NRT-13. Интерфейс выбора этих параметров требует согласования.

В закреплённом окружении Starlette 1.10.0 уже переводит ошибку заголовка части
в `400 invalid_request`. Регрессионная проверка закрепляет этот ответ.
Отдельно воспроизведён приём неполной формы с `202`. Маршрут теперь проверяет,
что парсер дошёл до закрывающей границы, и возвращает `400 invalid_request`
до сохранения. Проверены корректный повтор с тем же ключом и закрытие
временного файла незавершённой части. Нулевой символ в имени файла, договоре
и строковых полях адреса отклоняется с `422 invalid_input` до записи в PostgreSQL.

На Windows с Python 3.12.12 и изолированным PostgreSQL 18.4 прошли
123 теста, в том числе сохранение файлов, ошибки и повтор после сбоя. Команда
`uv run --frozen --with jsonschema==4.26.0 pytest tests --ignore=tests/ml_module -q`
проверяет backend и контракт. Проверки `ruff check src migrations tests`,
`ruff format --check src migrations tests`, `docker compose config --quiet`
и `git diff --check` также прошли. В тестах остаётся предупреждение Starlette
об использовании `httpx` в `TestClient`. Для контейнерного прогона нужен CI.

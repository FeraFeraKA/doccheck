# NRT-95 — запуск документного worker с адаптером

[NRT-95](https://linear.app/andreiakimov/issue/NRT-95/podklyuchit-ml-adapter-k-worker-i-sohraneniyu-rezultata),
[NRT-94](https://linear.app/andreiakimov/issue/NRT-94/realizovat-adapter-vyzova-gotovogo-ml-modulya)
и [NRT-93](https://linear.app/andreiakimov/issue/NRT-93/soglasovat-interfejs-ml-modulya-i-rezultat-obrabotki)
прочитаны 14 ноября 2026 года. База `43c3f25823debc26cb6c86e065e4e3185d53b4e5`.

`compose.yaml` добавляет профиль `document-worker`. Сервис использует
существующий CLI `run_worker --processor module:callable`. Код адаптера
устанавливается в явно выбранный образ, том исходных файлов подключается в
режиме чтения. Миграция и PostgreSQL должны быть готовы до запуска. Обычный
Compose поднимает синтетический worker. Документный worker запускается
только при активации профиля или явном запуске сервиса. Пустой или
неимпортируемый адаптер останавливает процесс до захвата заданий.
В `backend/README.md` описан запуск. В `.env.example` указан пустой параметр.

В двух новых проверках FastAPI принимает синтетический пакет без области,
отдельный процесс worker загружает тестовый адаптер, а GET читает итог из
PostgreSQL. Успешный результат помечен `synthetic=true`. Исключение адаптера
сохраняется как безопасный `processing_failed`, API результата возвращает
`409 run_failed`. Тестовые функции находятся в `backend/tests/`, вне
runtime-образа. На PostgreSQL 18.4 прошли 60 тестов загрузки, чтения и
worker, включая две проверки CLI. Сохраняется предупреждение TestClient
об устаревшей поддержке `httpx`.

В Compose CI добавлены проверка отключённого профиля по умолчанию и
контейнерная проверка отказа при пустом параметре. Локально прошли
`docker compose config`, проверка явной команды, зависимости от миграции,
закрытой backend-сети и тома для чтения. Локальный CLI с пустым параметром
завершился с кодом 2. Ruff, проверка формата и OpenAPI прошли.

Docker daemon на этом компьютере недоступен. Фактический запуск
Compose-профиля проверяется в GitHub CI. Образ с реальным адаптером, его
зависимости и запуск обработки ждут готового рабочего конвейера NRT-94,
включая зависимости от извлечения и сверки. ML и OCR здесь не запускались.
Полный проход с интерфейсом относится к NRT-43.

# NRT-20 — адреса денежных ячеек растровой КФЗ

Рабочая проверка начинается с уже адресованной годовой строки КФЗ.
Встроенный Windows OCR повторно читает отдельные ячейки исходной страницы.
Две бинаризации изображения должны согласовать верхнюю и нижнюю линии
строки, вертикальные границы ячеек и горизонтальные линии шапки. Заголовок
статьи должен принадлежать своей секции таблицы и содержать код статьи.
Для зарплаты и взносов дополнительно проверяется отдельный заголовок
итоговой колонки под секцией. Соседняя вложенная подколонка не используется
как итог.

Публикуется только числовое значение, которое совпало после двух разных
масштабирований ячейки и не имеет конкурирующего числового прочтения.
Это согласие двух чтений одним OCR, а не независимая экспертиза.
Неопознанная сумма остаётся пустой и не влияет на частичные суммы
первичных документов. Адрес денежного доказательства — внутренняя
область найденной ячейки, нормализованная к исходной странице PDFium.
Изображения, текст OCR и суммы прогона не публикуются в Git.

На разрешённой локальной PDF КФЗ подтвердились три статьи из четырёх.
На оставшейся статье повторился неоднозначный символ, сумма оставлена
пустой. Адреса и прочитанные цифры локально проверены по оригиналу.
Тесты создают собственную таблицу и проверяют ноль, границы, соседнюю
подколонку и конфликтующие показания.

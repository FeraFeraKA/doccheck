# NRT-94 — вызов модуля идентификации из адаптера наблюдений

[NRT-94 в Linear](https://linear.app/andreiakimov/issue/NRT-94/realizovat-adapter-vyzova-gotovogo-ml-modulya)
и NRT-93 прочитаны 14 ноября 2026 года. Основа —
[согласованная граница NRT-93](../ml-module-boundary.md).

## Вызов

Вызов `identify_documents(documents, synthetic=...)` принимает готовые
`ObservedDocument` с SHA-256, локальными путями и адресными наблюдениями.
Каждое наблюдение хранит текст, существующий `Locator` и происхождение
`native` или `ocr`. Область координат и инвентарь листов предоставляет
источник наблюдений для той же версии файла. Адаптер проверяет геометрию,
сопоставляет тип адреса с форматом и сверяет лист с переданным инвентарём.
Формат оригинала и правильность полученного текста остаются
ответственностью извлечения.

Адаптер вызывает установленный `doccheck_ml.process_documents` напрямую,
последовательно и без HTTP. Любое OCR-наблюдение переводит документ в
`scan` для модуля, а исходное происхождение каждого фрагмента сохраняется.
Пути передаёт доверенная локальная сторона. Модуль сверяет байты с SHA-256
и сообщает о недоступных или изменённых файлах по ID. При отсутствии модуля
адаптер возвращает типизированную ошибку доступности. Установка пакета в
контейнер и вызов из реального worker относятся к NRT-95.

## Результат

Суммы, реквизиты, типы и стороны остаются кандидатами. Адрес возвращается
только при однозначном совпадении доказательства с переданным наблюдением.
Структурные адреса DOCX хранятся рядом с наблюдением, поскольку текущий
модуль принимает для DOCX только текст. Неоднозначный обратный поиск
помечается `source_ambiguous`. Сохраняются версии, признак синтетики,
ошибки файлов, признаки ручной проверки, конфликты, проверенные группы
одинаковых SHA-256 и пары для дальнейшего рассмотрения.

Адаптер не присваивает статусы финансовой сверки. Предложения модели без
ссылки на наблюдение не получают адрес. Решения о сумме, её роли, периоде,
статье и полноте останутся за соответствующими правилами ядра.

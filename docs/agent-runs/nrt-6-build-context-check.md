# NRT-6 — проверка контекста сборки и файловых систем образов

[NRT-6](https://linear.app/andreiakimov/issue/NRT-6/repozitorij-okruzhenie-i-dostupy) прочитана 14 ноября 2026 года. База `f2781e1acd818a35593a1f4d8545a42cd9cb1ed2`.

В `.github/workflows/compose.yml` добавлены синтетические маркеры в `secrets/`, `pgdata/` и в файле `.key` внутри каталога backend, который попадает под `COPY`. Существующая проверка контекста сборки требует отсутствия этих путей. После сборки CI получает ID образов `api` и `frontend` из контейнеров Compose, создаёт из этих образов временные незапущенные контейнеры без томов Compose и проверяет только имена в экспортированной файловой системе. Временные контейнеры и список имён удаляются. Образ backend используется также worker и миграциями.

Локально прошли разбор YAML, `bash -n` для всех шагов, `git check-ignore` для трёх новых путей и `git diff --check`. Проверка с подменой команд подтвердила успех без маркера, отказ при маркере и отказ с очисткой при сбое экспорта. После независимого замечания этот же шаг проверен на кодах `grep` 0, 1 и 2 под `bash -e -o pipefail`: только отсутствие совпадений даёт успех, ошибка чтения завершает шаг и удаляет временный контейнер. Docker локально не запускался. Реальная проверка сборки выполняется в Compose CI. Прогон проверяет синтетические имена в итоговой файловой системе, без аудита содержимого слоёв, истории Git, закрытых данных и доступов.

# NRT-108 — подготовка облачного демо DocCheck

[NRT-108](https://linear.app/andreiakimov/issue/NRT-108/razvernut-demo-doccheck-na-vercel-i-render)
прочитана 14 ноября 2026 года. База финальной сверки `e8d2148341244470cb296d21998ef9feeeaecb67`.
Исходный репозиторий для привязки — `VCyberPunk2077/doccheck`.

## Доступ и варианты запуска

- Render MCP видит `My Workspace`. В нём четыре web-сервиса других проектов
  и нет PostgreSQL. Проект DocCheck пока не найден. При публикации потребуется
  выбрать этот workspace или указанный владельцем другой и сверить доступные
  бесплатные слоты. [Render Dashboard](https://dashboard.render.com/)
- Vercel MCP получил `403` при поиске проектов в `feras-projects-0472e30c`.
  Для продолжения нужен доступ к этому scope, затем сверка проекта, репозитория,
  среды Preview и выбранного коммита. Разовый URL авторизации передаётся
  владельцу отдельно. [Vercel Dashboard](https://vercel.com/dashboard)
- Бесплатный Render Web Service хранит файлы до перезапуска и может засыпать.
  Бесплатная PostgreSQL истекает через 30 дней. Отдельный Render Background
  Worker и постоянный диск требуют подходящих ресурсов. Диск одного сервиса
  нельзя разделить между API и другим сервисом обработки. Для работы с файлами
  нужны защищённое окружение и общее устойчивое хранилище либо проверенная
  схема запуска обоих процессов с одним диском. [Render Free](https://render.com/docs/free) · [Render Disks](https://render.com/docs/disks)

## Подготовленный режим

`render.yaml` описывает бесплатный web-сервис и выделенную бесплатную
PostgreSQL 18 в одном регионе. Автодеплой и автоматические preview отключены.
БД доступна по внутреннему адресу. `render_demo` требует `DOCCHECK_PUBLIC_DEMO=1`
и отдельный `DOCCHECK_RENDER_DATABASE_URL`, проводит миграции до запуска
Uvicorn и запущенного отдельным процессом синтетического worker. Оба процесса
живут в одном экземпляре Web Service. Реальный конвейер не подключён.
[Blueprint YAML](https://render.com/docs/blueprint-spec) · [Render Deploys](https://render.com/docs/deploys)

Прямой Render API блокирует маршруты рабочих заданий `/api/v0/runs`, включая
загрузку, историю, результаты, оригиналы и экспорт. Пример результата встроен
в UI, `/api/synthetic-jobs` демонстрирует настоящее сохранение состояния
синтетического задания в БД. В облачном мастере кнопки и поля отправки файлов
отсутствуют. В локальной установке остаётся обычный API документов.

Vercel использует `frontend/vercel.mjs`, pnpm 12.14.0 и выход `dist`. Для
проектной настройки выбрать Root Directory `frontend`, включить **Include
source files outside of the Root Directory** для двух синтетических JSON
и выбрать совместимый Node.js 24.x. В Preview задать
`DOCCHECK_RENDER_ORIGIN` как точный HTTPS-origin выбранного Render Web Service
на `onrender.com`, без завершающего `/`. Код конфигурации маршрутизирует
`/api` и `/health` через этот origin и восстанавливает прямые SPA-маршруты
`/checks/*` и `/log`. Сборка включает синтетический режим. Git auto-deploy
отключён. [Vercel Config](https://vercel.com/docs/project-configuration/vercel-ts) · [Monorepos](https://vercel.com/docs/monorepos/monorepo-faq) · [Node.js versions](https://vercel.com/docs/functions/runtimes/node-js/node-js-versions)

- На предыдущей базе `104b4e6cb1a5ab1bb6ab0ba6be47b11223043d8f` прошли
  202 backend-теста с PostgreSQL 18.4, 134 Vitest, lint, проверка типов и
  production build синтетической версии. Обновление базы добавило файлы
  NRT-22, сохранив файлы развёртывания и их тесты.
- Экспорт конфигурации `vercel.mjs` принят официальной JSON Schema.
  Принят точный HTTPS-origin Render, четыре некорректных значения отклонены.
  Синтаксис `render.yaml` и согласованность ссылок проверены локально по
  официальной спецификации и схеме. Автоматический запуск Render CLI
  validation остаётся на следующий этап. Локальная загрузка схемы Render
  по HTTPS завершалась по тайм-ауту.

## Проверка перед публикацией

1. После отдельного разрешения сверить owner, Preview и один SHA на обеих
   платформах. Перед подключением Vercel проверить прямой Render `/health`,
   состояние `alembic_version`, ответ `503` на POST файлов и чтение оригинала.
2. Через Preview открыть прямой `/checks/synthetic-example`, перезагрузить
   и провести цикл `/api/synthetic-jobs`. Проверить отказ документных маршрутов
   через Vercel и напрямую. Сохранить URL, SHA и фактический журнал проверки.
3. Для отката использовать предыдущую проверенную синтетическую версию на
   каждой платформе. При смене сборки сверять совместимость с текущей
   версией БД. Если безопасной версии нет, убрать Preview из доступа и
   остановить сервис. Схема не откатывается автоматически.

Локальный Chromium открыл прямой SPA-адрес после перезагрузки через временный
прокси, построенный из конфигурации Vercel, и показал мастер без поля выбора
файла. В отдельной PostgreSQL 18.4 запуск `render_demo` применил миграции.
Через прокси создано синтетическое задание, отдельный worker сохранил
`completed`. Прямой и проксированный API отказали в загрузке и выдаче
оригиналов. Это проверка локального аналога, облачные build, rewrite,
лимиты платформы и долговечность БД в облаке предстоит подтвердить.

На этом шаге выполнена только подготовка. Публичного URL и проверенного
облачного деплоя нет. NRT-108 остаётся частичной: публичная загрузка,
долговечность исходных файлов и рабочий адаптер не приняты.

# NRT-108 — синтетическая очередь для воркера на компьютере

[NRT-108](https://linear.app/andreiakimov/issue/NRT-108/razvernut-demo-doccheck-na-vercel-i-render)
требует отдельно проверенный Preview на синтетике, с документами и проверяемым
состоянием API. [NRT-95](https://linear.app/andreiakimov/issue/NRT-95/podklyuchit-ml-adapter-k-worker-i-sohraneniyu-rezultata)
задаёт сохранение результата воркера, идентичность входных файлов и отделение
статуса выполнения от предметных выводов. Этот срез выполняет протокол между
локальным воркером и API. Облачные сервисы и вход браузера не менялись.

## Локальная проверка

Используйте отдельный PostgreSQL, каталог файлов и API на loopback. API требует
`DOCCHECK_PUBLIC_DEMO=1` и `DOCCHECK_HOSTED_WORKER_SHA256` с SHA-256 случайного
секрета длиной не менее 32 ASCII-символов. При пустом хеше воркерные маршруты
отключены. Сам секрет передаётся только процессу воркера в переменной
`DOCCHECK_HOSTED_WORKER_TOKEN`. Он не передаётся в параметры URL и не включается
в браузерную сборку. У API и воркера остаются обычные локальные зависимости.

1. Примените миграции через `uv run --project backend --locked alembic -c backend/alembic.ini upgrade head`.
2. Подготовьте заведомо синтетические XLSX КФЗ и DOCX. Манифест должен содержать
   `synthetic: true`, `report: {name, sha256}` и `documents: [{name, sha256}]`.
   Пин самого манифеста получают из проверенного артефакта, а не принимают из
   пользовательской загрузки. Файлы лежат рядом с манифестом под простыми именами.
3. Из корня репозитория поместите пакет в очередь через
   `uv run --project backend --locked python -m doccheck_backend.hosted_seed PATH MANIFEST_SHA256 REQUEST_UUID`.
   Команда доступна оператору. Она сверяет хеши и атомарно регистрирует
   допуск пакета и задание. Повтор с прежним UUID сохраняет исходное задание
   при совпадении с пакетом. API произвольной загрузки по сети закрыт.
4. Запустите API в выбранном окружении. На компьютере воркера запустите
   закреплённую Ollama по [инструкции v3.2](../../bench/e2e_v32_20261114/README.md).
   Затем из корня репозитория выполните:

   ```sh
   uv run --project backend --locked --with-requirements bench/e2e_v32_20261114/requirements.txt python -m doccheck_backend.hosted_worker --origin http://127.0.0.1:18037 --processor doccheck_backend.v32_adapter:process --once
   ```

   Для удалённого API используется явный HTTPS-origin. Запросы воркера не
   перенаправляются и не наследуют системный HTTP-прокси. Ollama принимает
   только локальные вызовы, а воркер не слушает сеть.

## Границы

Протокол допускает максимум восемь первичных документов, по 2 МиБ каждый,
и результат до 1 МиБ. Срок текущей аренды 60 секунд, воркер запрашивает
продление раз в 15 секунд. По истечении аренды следующий захват выбирает
повтор, а после трёх попыток или общего дедлайна в 15 минут фиксирует отказ.
Старый идентификатор не может продлить или завершить новую попытку.
После завершения повтор идентичного результата не меняет запись.
При потере соединения вычисляющая задача может завершиться в локальном
потоке, но её просроченный результат не будет сохранён. Временные файлы
удаляются после завершения или отказа.

Выбран один доверенный воркер и один ротируемый секрет для отдельного
синтетического стенда. Для нескольких участников нужны отдельная
аутентификация браузера, проверка владельца во всех маршрутах создания и
чтения, ограничение частоты и политика хранения. Пользовательские профили
и развёртывание описаны в [проекте стенда](../design/local-worker-hosted.md).
Обычный режим публичного демо без настроенного хеша не даёт доступ к очереди.

## Проверки

Проверены HTTP-протокол и сохранение через отдельный PostgreSQL, включая
скачивание оригиналов, проверку их SHA-256, устаревшую аренду, повтор
завершения, отклонение неверного секрета и запрет публичной загрузки.
Управляемый адаптер в тесте явно синтетический, результат помечается как
синтетический по источнику пакета независимо от флага в ответе воркера.

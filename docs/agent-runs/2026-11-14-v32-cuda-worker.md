# DocCheck v3.2 с CUDA, адресами источников и синтетическим тестом

Основа пайплайна — `db656e2` из `nrt-92-local-pipeline-v3-2`.
Изменения подготовлены отдельной веткой от `origin/main`.

В `QwenReader` перенесено применение маски LLGuidance на операции MLX
с поддержкой CUDA. Worker `run_worker --v32` использует локальные веса
Qwen и обязательный LoRA. Его вход — сохранённый пакет с SHA-256
и областью сверки, если её указал пользователь. Он возвращает CheckJob,
результат с адресами, причины исключения и ошибки отдельных файлов.
Обработка проверена в Ubuntu 24.04 WSL 2 на RTX 2060 6 ГБ, CUDA 12.9,
PostgreSQL 16 и Tesseract rus+eng. Версии Python-пакетов закреплены.

Адресная сверка поддерживает PDF/PNG и шаблоны XLSX КФЗ. Для
разлинованной КФЗ без явных границ пользователь указывает область
и строку. Источники сумм первички поддерживают PDF, PNG, DOCX и XLSX.
У принятого слагаемого есть адреса суммы, договора, периода и статьи.
Локальные правила определяют допуск. Чтение Qwen со скана остаётся
предложением реквизита. Система сообщает о неполной КФЗ или неполном
чтении источника. Статус статьи при неизвестной полноте — unverified.

Закрытый пилот обслуживает UI и API по HTTPS на loopback с
аутентификацией. Проверены перезапуск, отказ без доступа, восстановление
копии БД в изолированную БД и сверка SHA-256 сохранённых файлов. Публичный
тест запускает один сгенерированный комплект без пользовательских
загрузок. Для него используются отдельные PostgreSQL, хранилище,
сборка frontend и Unix-сокет API.

Связанная [задача NRT-92](https://linear.app/andreiakimov/issue/NRT-92/izuchit-gotovyj-ml-modul-i-ego-interfejs)
актуализирована 13.11.2026 в 18:28 UTC. Её критерии охватывают расположение,
версию и вызов готового модуля, зависимости, фактические входы, выходы,
ошибки и ограничения этапов КФЗ/OCR/сопоставления, пробный синтетический
запуск или причину блокировки, правила хранения данных и открытые
вопросы для Семёна. Веса использованы без обучения и изменения.
Закрытые данные, эталоны и веса в выпуск не включены.

Команды описаны в [backend/README.md](../../backend/README.md).
Измерения 50 синтетических комплектов и закрытые результаты хранятся
локально. Синтетика проверяет один набор семейств макетов с разными
суммами, периодами и порядком документов. Предметная приёмка проводится
владельцами проекта.

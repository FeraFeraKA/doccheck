# NRT-95 — локальные результаты v3.2 через воркер

[Задача NRT-95 в Linear](https://linear.app/andreiakimov/issue/NRT-95/podklyuchit-ml-adapter-k-worker-i-sohraneniyu-rezultata)
сверена 14.11.2026. Воркер вызывает обработчик вне HTTP-запроса. Результат
и адреса источников проходят валидацию существующего контракта перед
сохранением. Ошибки чтения файлов и состояние задания фиксируются отдельными
полями. Пользователь подтвердил первый сценарий с КФЗ XLSX и актом DOCX.

Точка входа: `doccheck_backend.v32_adapter:process`. Воркер использует
сохранённые ID и хеши, определяет договор и период по поддерживаемому
шаблону КФЗ и передаёт первичку в существующий конвейер v3.2. Перед
извлечением проверяется контрольная сумма локальной модели. Рабочие
копии и промежуточные файлы конвейера удаляются после обработки.

Адаптер принимает слагаемое, когда модельный результат совпадает с
исходными суммой, договором, периодом и адресуемым основанием отнесения
к статье. Отдельные строки КФЗ ссылаются на ячейки, первичка — на абзацы
или ячейки таблиц. Полнота пакета остаётся неизвестной, поэтому найденные
частичные суммы отображаются как `observed_evidence_sum` при `unverified`.
Документ с неопределённым адресом источника или несовпадающей областью
требует просмотра. Точные копии исключаются по хешу. Конфликтующие
реквизиты дубликатов оставляют документы за пределами частичной суммы. Путь сравнения
поддерживает шаблон XLSX целиком, без выбора отдельной строки КФЗ,
со структурными доказательствами из поддерживаемых актов DOCX.

Проверки в рабочей копии: `uv run --frozen pytest -q tests/test_v32_adapter.py`
из `backend` покрывает чтение синтетических файлов, вызов
существующего конвейера с подменой только Ollama HTTP, идентичность результата
и адресов, неизвестную и неоднозначную сумму, конфликт копий и повреждённую первичку.
В полном локальном backend-прогоне тесты, которым нужна отдельно настроенная
тестовая БД, пропущены. Проверка с реальной моделью и браузером ведётся
отдельно в [NRT-43](https://linear.app/andreiakimov/issue/NRT-43/skvoznaya-integraciya-i-knopka-demo).

После ревью #89 проверены типы денежных ячеек КФЗ и зависимостей формул.
Для денежного фрагмента требуется однозначная текущая стоимость услуг или
работ. Иные и неоднозначные строки итога блокируют допуск суммы.
Совпадения подтверждённых номера, договора и периода рассматриваются
до дедупликации v3.2. Разница неподтверждённых контрагентов не разделяет их.
Неполное чтение структуры DOCX отражается как техническая ошибка файла.

## Цель и критерии NRT-6

Поддерживать общий репозиторий DocCheck, понятные правила работы, настройки
окружения и режим данных. Николай отвечает за репозиторий и интеграцию,
владельцы направлений проверяют свои доступы.

- [ ] В репозитории есть `frontend/`, `backend/`, `docs/` и `contracts/`.
  Тесты размещены в `frontend/tests/` и `backend/tests/`. Рабочие данные
  без разрешения на публикацию исключены из Git.
- [ ] README, CONTRIBUTING и AGENTS отражают структуру, работу в ветках
  и worktree, пользовательскую директорию и команды проверок.
- [ ] Владелец и доступы участников проверены после передачи. Способ
  клонирования документирован, ссылка и связанные настройки актуализированы.
- [ ] Есть `.env.example` без секретов и исключения для локальных настроек,
  результатов и ключей. При появлении образов проверен `.dockerignore`.
- [ ] Описаны ограничения передачи данных, хранения независимого эталона
  и доступности файлов облачным агентам. Разрешённый обезличенный комплект
  выделен явно.
- [ ] Проверены изменённые файлы и исключения. Отсутствие ключей и эталона
  в истории и runtime заявляется после соответствующей проверки.

## Изменения и проверки

- В `.gitignore` перенесены правила для корневых `/pgdata/` и `/secrets/`.
  В `docs/data-policy.md` описаны границы доступа при использовании
  worktree, Git-исключений и среды с полным доступом к файловой системе.
- Текущие шаблон окружения, правила сборки и CI уже есть в `main`.
  Основание для текущего PR составляют два изменения выше и этот отчёт.
- `git check-ignore -q --no-index` подтвердил восемь исключаемых путей.
  Среди них корневые `pgdata/`, `secrets/`, локальные файлы окружения,
  закрытые данные и вложенные worktree. Семь проверяемых путей доступны
  для Git. Среди них `.env.example`, код, схема и разрешённый README
  комплекта, а также пробные одноимённые папки внутри исходников.
- В текущем индексе отсутствуют файлы под корневыми `pgdata/` и `secrets/`.
  `git diff --check` прошёл.

## Открытые проверки

Этот срез охватывает текущие файлы настроек и документации. Аудит истории
Git, сборка и инспекция runtime, фактическая изоляция закрытых данных
и проверка доступов участников требуют отдельных проверок.

# NRT-64 — каталог ошибок и генератор синтетических кейсов

[Задача Linear](https://linear.app/andreiakimov/issue/NRT-64/katalog-oshibok-nashej-sistemy-i-sinteticheskie-test-kejsy) и связанные NRT-33, NRT-34 и NRT-40 прочитаны напрямую 13.11.2026 в 04:48 МСК. Назначение `n90-20261112-2352 / a3`. База `319f64292d39be965e52e95cf34dfb072e866e16`.

- `docs/research/error-catalog.md` описывает 26 ошибок OCR, парсинга,
  расчёта, сопоставления и вывода статуса. Для каждой указаны причина,
  проявление, статус, защита и риск К3. Десять сценариев выделены по
  риску ложной тревоги. Проверенные правила и предпосылки QA описаны
  отдельно. Готовый справочник правил в базе отсутствовал.
- `research/error-catalog/generate.py`, `sample.json` и `test_generate.py`
  дают воспроизводимый набор из вымышленных реквизитов и денежных строк.
  Приложение не импортирует генератор и ожидаемые статусы.

ТЗ и разрешённый набор из 25 файлов сверены локально. Для DOCX и XLSX
проверены структура и поля, для PDF текст и слои, для четырёх сканированных
PDF и PNG выполнено локальное чтение без публикации текста. Проверены
дубликаты, пустой кэш формул ведомостей и раздельные поля взносов.
Закрытые материалы и независимый эталон не использовались.

Python 3.12.12: генератор записал 26 примеров. Семь тестов
`python -m unittest discover -s research/error-catalog -v` прошли.
Проверены повторная генерация с тем же seed, разные суммы, реквизиты
и порядок, согласованность ожидаемых статусов, `null` и нуля,
побайтовая копия с несколькими операциями и арифметика НДС и округления.
Ruff check, Ruff format check и `git diff --check` прошли.

По [ревью a3-r2](https://github.com/VCyberPunk2077/doccheck/pull/13#issuecomment-6842051118)
уточнены четыре сценария. В C02 неверная ставка указана в самом УПД.
В C07 зачтён удержанный НДФЛ и проверены полное и неполное удержание.
В M01 у двух операций одной суммы разные ячейки. В F01 профиль
сравнения задаёт обязательные источники.

Фикстуры проверяют структуру сценария, арифметику и однозначность
выдуманных предпосылок. Прогон реального OCR, классификатора и финансового
конвейера, оценка на скрытых данных и проверка предметной разметки
остаются отдельными шагами. Владельцу направления нужно проверить
ожидаемые статусы при предметной приёмке.

# NRT-86 Машинный контракт результата сверки

[NRT-86](https://linear.app/andreiakimov/issue/NRT-86/pydantic-i-sinteticheskij-primer-soglasovannogo-kontrakta) и
[NRT-18](https://linear.app/andreiakimov/issue/NRT-18/edinaya-shema-dannyh-pydantic)
прочитаны 13 ноября 2026 в 05:18 МСК. Назначение `b3`, запуск
`n90-20261112-2352`, база `f0137d5df0ecaf9d090da1dc184822f56e4f25db`.
Модели, тесты, схема и пример реализуют семантику
[NRT-85](../result-source-contract.md).

## Покрытые критерии NRT-18

- Модели `CheckJob` и `CheckResult` определяют единственный машинный
  источник версии `doccheck-check-result/1`. Схема и пример доступны
  в [contracts](../../contracts/README.md).
- Состояния задания, решений по файлу, парсинга и показателей имеют
  отдельные поля. Денежные строки, наблюдаемая сумма, ожидаемое значение,
  дельта и известный ноль проверяются отдельно.
- Для PDF/PNG обязателен адрес фрагмента, для XLSX — лист и диапазон, для DOCX
  — абзац или ячейка. Роли доказательств суммы, договора, периода и статьи
  проверяются по отдельным ссылкам. Две операции с равной суммой и разными
  адресами сохраняются после исключения копии файла.
- Модели проверяют основание полноты, версии, принадлежность ссылок заданию,
  связь с первичной причиной и итоговые счётчики. Семантическую проверку
  прочитанного фрагмента и его привязку выполняет адаптер при обработке.

## Проверки

- Сверены ТЗ, оба README и все 25 разрешённых файлов, включая скан КФЗ,
  10 XLSX и документы с текстовым слоем и без него. Файлы совпадают с
  рассмотренными в NRT-85. Публичный пример содержит только вымышленные
  документы, адреса и значения. Эталон и holdout не использовались.
- На Python 3.12.12 и Pydantic 2.14.3 прошли 100 проверок контракта,
  включая семь с независимым валидатором Draft 2020-12.
  Проверены генерация и совпадение схемы, сохранение модели при JSON
  round-trip, значения денег, адреса, дубли, доказательства и ошибки.
- Локальный backend-прогон с валидатором схемы дал 101 успешный тест.
  Три теста с PostgreSQL ожидают CI с настроенной базой.
- Независимый валидатор Draft 2020-12 принял схему и оба синтетических
  примера и отклонил 18 некорректных вариантов. Ruff check, Ruff format check и
  `git diff --check` прошли.
- По двум замечаниям [Codex к PR №14](https://github.com/VCyberPunk2077/doccheck/pull/14#pullrequestreview-5885305871)
  добавлены проверки подмены ожидаемой суммы, неподтверждённого нуля и
  двух записей с адресами `C6` и `C6:C6`. Версия 1 проверяет операцию
  `sum`. При отсутствии поддерживаемой операции сохраняется наблюдаемая
  сумма, а ожидаемое значение остаётся `null`.
- После [независимого ревью](https://github.com/VCyberPunk2077/doccheck/pull/14#pullrequestreview-5885533126)
  добавлены регрессии для повторного адреса PDF, непригодных источников и
  противоречий области, состояний ошибок и связи первичной причины со строкой.
  Синтетический фрагмент NRT-85 прошёл валидацию той же моделью и схемой.
- После [повторного ревью](https://github.com/VCyberPunk2077/doccheck/pull/14#pullrequestreview-5885819846)
  добавлены проверки противоречивых чтений суммы и единицы, включая чтения,
  отсутствующие в ссылках выбранной строки. Слагаемое проверяет реквизиты
  первичного источника либо адресную связь с другим допущенным документом.
  Проверены отклонение подмены реквизитами отчёта и сохранение конфликта в
  непроверенной строке.
- После [ревью b3-r4](https://github.com/VCyberPunk2077/doccheck/pull/14#pullrequestreview-5886005519)
  проверены транзитивные связи точных адресов PDF, отсутствие двойного
  учёта одного фрагмента и сохранение отдельных операций. Противоречивые
  чтения опорного реквизита исключают его из междокументного подтверждения.
  Оба чтения можно сохранить как причину `unverified`.
- [Замечание Codex](https://github.com/VCyberPunk2077/doccheck/pull/14#discussion_r4559705128)
  воспроизведено для договора, периода и статьи. Конфликтующие чтения
  каждого реквизита проверяются по тому же адресу. Совместимые частичные
  даты периода допускаются.
- После [ревью b3-r5](https://github.com/VCyberPunk2077/doccheck/pull/14#pullrequestreview-5886449110)
  проверена связь нескольких номеров строк через одну точную рамку для
  суммы и опорного реквизита. Два разных точных фрагмента требуют уточнить
  ссылку по номеру строки даже при одинаковых суммах. Проверены
  несовместимые границы периода из разных адресов и сохранение неизвестных дат.
- Дополнительные регрессии проверили договор, период и статью, когда
  несогласованное чтение не входит в ссылки слагаемого и относится к тому
  же PDF-фрагменту через другой номер строки. Чтение из отдельного точного
  фрагмента на той же строке сохраняется отдельно.
- После [ревью b3-r6](https://github.com/VCyberPunk2077/doccheck/pull/14#pullrequestreview-5886749205)
  добавлена проверка адресов и чтений, на которые опирается полнота.
  Конфликт обязательного слагаемого исключает подтверждение частичного
  результата. Проверены сохранение наблюдаемой суммы с причиной
  `unverified`, неоднозначная строка PDF, противоречивые реквизиты,
  совместимые даты и независимое основание полноты.
- После [ревью b3-r7](https://github.com/VCyberPunk2077/doccheck/pull/14#pullrequestreview-5886978309)
  схема требует слагаемые для наблюдаемой суммы, ссылку для значения
  отчёта и причину для расхождения. Draft 2020-12 и Pydantic отклонили
  все три мутации. Доказанный ноль и оба синтетических примера приняты.
- После [ревью b3-r8](https://github.com/VCyberPunk2077/doccheck/pull/14#pullrequestreview-5887271206)
  схема требует хотя бы одну дату в наблюдении периода и состояние
  `exclude` у побайтовой копии. Основание полноты `dataset_fixture`
  допустимо только при `synthetic: true`. Pydantic и Draft 2020-12
  подтвердили оба варианта одной известной даты, исключённую копию и
  `manifest` при `synthetic: false`, а также отклонили все три мутации.

## Передача и ограничения

Николаю передаются схема обмена и пример для API и UI. Семёну передаются
модели, правила адресации и допуск слагаемых для адаптера. Критерий
независимого ревью и человеческая приёмка ещё требуют подтверждения.
Вопросы о границах периода, профиле полноты, сторно и заменах версий
остаются в NRT-85. Реальный OCR/Qwen, офлайн-обработка и подключение к
маршрутам относятся к следующим задачам.

# NRT-39 — диагностика PDF, требующего пароль

[NRT-39](https://linear.app/andreiakimov/issue/NRT-39/ustojchivost-bitye-fajly-ne-ronyayut-zapusk)
сверена 14 ноября 2026 года, база `5904e2adbec52a73ce66d1ebd17845ce17a22504`.

При открытии PDF через pdfplumber обёрнутая ошибка `PDFPasswordIncorrect`
возвращается как пофайловая диагностика `encrypted_pdf` без наблюдений.
Ошибки чтения других типов сохраняют прежнюю диагностику. Параметр
для пароля, повторная попытка открытия и изменение worker не добавлялись.

Фикстура `backend/tests/fixtures/encrypted-empty.pdf` — пустая синтетическая
страница, созданная `pypdf==6.21.4` из существующего инструментария
NRT-89. Для воспроизведения вызовите `PdfWriter.add_blank_page(width=72,
height=72)`, `PdfWriter.encrypt` с непустым синтетическим параметром
и алгоритмом `RC4-128`, затем `PdfWriter.write`. В тестах используется
готовый файл, зависимости проекта остались прежними.

Прошли 123 профильных теста PDF и Office, Ruff, проверка форматирования,
lock-файла и `git diff --check`. Проверка влияния ошибки на полноту и
продолжение рабочего пакета относятся к интеграции NRT-39.

# Режим данных

`data/` — локальная директория, полностью исключённая из Git. В среде облачного coding-agent здесь допустимы только синтетические или явно разрешённые для него материалы. Закрытые оригиналы, OCR-текст, превью и результаты должны находиться в отдельной среде обработки без доступа облачного агента.

`.gitignore` ограничивает обычное добавление файлов в Git. Worktree разделяет рабочие изменения. Ни один из этих механизмов не запрещает агенту читать файлы. Перенос оригиналов в соседнюю папку на машине с полным доступом агента тоже не создаёт изоляцию. Для закрытых данных нужна отдельная машина/среда с проверенными ограничениями доступа; они не добавляются в workspace, вложения чата и вывод инструментов.

В текущей сессии агент имеет полный доступ к файловой системе. Наличие `.gitignore` не означает безопасную изоляцию закрытого набора. Получение и обработка такого набора в этой среде остаются за пределами подготовки каркаса до подтверждения допустимого режима.

Независимые эталоны и holdout хранятся отдельно от runtime. Их нельзя включать в образы, фикстуры API или подсказки для вычисления результата.

В Git разрешены исходный код, общая схема и явно синтетические примеры. Исключение каталога через .gitignore не проверяет содержимое файлов в других местах: перед коммитом нужно просматривать diff и список файлов.

Не публиковать первичные документы, OCR-текст, скриншоты с их содержимым, реальные результаты, секреты и подробные логи. До подтверждённого разрешения облачным агентам передаются только код, синтетика и допустимые технические сообщения. Выдача архива на хакатоне сама по себе не делает документы открытыми.

Подтверждение разрешения должно указывать конкретные материалы, получателя/сервис, цель и допустимый объём передачи. Публичность репозитория не меняет режим исходных данных. Внешним моделям передаются данные организаторов, OCR-текст и скриншоты только в пределах подтверждённого разрешения.

Перед публикацией проверяются staged diff и история Git. Добавление файла в `.gitignore` не удаляет ранее опубликованные данные из истории. Реальные данные и эталон не должны попадать в контекст сборки, слои runtime-образа или синтетические fixtures; проверка образов проводится после появления Dockerfile и Compose.

Приложение должно обрабатывать документы локально без внешних сервисов. Зависимости и веса можно подготовить до рабочего запуска. Проверка такого режима ещё предстоит.

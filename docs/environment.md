# Настройки окружения

В репозитории хранится только `.env.example`. Для локальной разработки скопировать его в `.env`:

```powershell
Copy-Item .env.example .env
```

Для Linux/macOS: `cp .env.example .env`. Не перезаписывать существующий настроенный `.env`.

| Переменная | Назначение | Текущее значение |
| --- | --- | --- |
| `DATABASE_URL` | Подключение backend и worker к PostgreSQL | Пустое; заполнить локально после подготовки БД |

В примере нет рабочего пароля и подключения к чужой базе. Драйвер, адрес сервиса в Compose, создание пользователя БД и загрузка настроек будут реализованы в согласованном каркасе. Сейчас приложение отсутствует, поэтому файл сам по себе не запускает БД и не проверяет подключение. API и worker должны использовать одну конфигурацию PostgreSQL.

В будущем загрузчик настроек должен завершать запуск с понятной ошибкой при отсутствующем `DATABASE_URL`, не выводя пароль или полный URL. Строка подключения не передаётся во frontend, публичные логи и ответы API. Внешний LLM API и его ключ не нужны для MVP.

Реальные секреты вводятся локально в соответствующей среде. `.env` защищён от обычного добавления в Git, но это не ограничение доступа к файлу. Облачному агенту следует передавать только шаблон без секретов; `.env` с реальными секретами должен находиться в изолированной от него среде запуска.

Корневой `.dockerignore` исключает данные, секреты, историю Git, локальные зависимости и результаты из будущего контекста сборки с корнем репозитория. Это предварительное правило: при реализации Dockerfile/Compose нужно проверить реальные контексты сборки, инструкции COPY и содержимое образов. Для другого корня сборки нужен соответствующий файл исключений. Сам по себе `.dockerignore` не исключает данные из bind mounts и volumes во время запуска.

# DocCheck

DocCheck помогает сверять карточку фактических затрат (КФЗ) с первичными
документами. Пользователь загружает КФЗ и подтверждающие файлы, а приложение
сохраняет пакет, показывает найденные значения и позволяет перейти к их
источникам. Проект создан для трека 5 хакатона МФТИ.

## Текущий этап

- Локальный интерфейс принимает КФЗ и первичные документы, показывает очередь
  и историю проверок. API сохраняет файлы в файловом хранилище, а задания,
  метаданные и результаты — в PostgreSQL; обработка выполняется отдельным
  процессом.
- Для сохранённого результата доступны таблица сверки, сведения об источниках,
  оригиналы файлов и выгрузка XLSX.
- Стандартный Docker Compose запускает технический контур и синтетический
  worker. Проверить его можно на странице `/system-status`. Документные
  задания при этом остаются в очереди, пока отдельно не запущен настроенный
  обработчик.
- В репозитории есть адаптер v3.2 для обработки документов с локальной
  моделью. Для него требуется отдельный документный worker.
- Если в PDF КФЗ есть страница только в виде изображения, текущий адаптер
  завершает проверку с `failed` без результата: достоверная область и суммы
  такого скана пока не подтверждаются. В доступных результатах строки
  возвращаются со статусом `unverified` при
  неизвестной полноте. Возможность считать строки подтверждёнными или
  расхождениями в этом рабочем пути ещё требует реализации и проверки.

## Начало работы

Нужны Git, запущенный Docker Engine с Linux-контейнерами и Docker Compose
с поддержкой `up --wait`. Первая сборка скачивает образы и зависимости
из реестров. Для запуска только технического контура модель не нужна.

```sh
git clone https://github.com/VCyberPunk2077/doccheck.git
cd doccheck
```

Скопируйте `.env.example` в `.env`, если `.env` ещё нет. В Linux/macOS:

```sh
cp .env.example .env
```

В PowerShell:

```powershell
Copy-Item .env.example .env
```

Откройте `.env` и задайте `DOCCHECK_DB_PASSWORD` случайной строкой из
латинских букв и цифр, например 32 шестнадцатеричными символами. Файл
`.env` содержит локальные настройки и не должен попадать в Git.

## Запуск каркаса через Docker Compose

Из корня репозитория:

```sh
docker compose up --build --wait
docker compose ps --all
```

Откройте [http://127.0.0.1:8080](http://127.0.0.1:8080) и перейдите в
«Проверку системы», чтобы создать синтетическое задание. Для загрузки
документов доступен мастер. После запуска проверки без отдельного
документного worker пакет останется в состоянии `queued`.

PostgreSQL сначала проходит проверку готовности, затем сервис `migrate`
применяет миграции. API, синтетический worker и интерфейс запускаются после
необходимых зависимостей. Состояние и журналы можно проверить командами:

```sh
docker compose ps --all
docker compose logs --tail=100 api worker
```

Для остановки и повторного запуска:

```sh
docker compose down
docker compose up --wait
```

Обычный `down` сохраняет задания и оригиналы в именованных томах
`postgres-data` и `run-files`. Команда `docker compose down --volumes`
удаляет эти данные.

### Настройка Compose

| Переменная в `.env` | Назначение |
| --- | --- |
| `DOCCHECK_DB_PASSWORD` | Пароль PostgreSQL для Compose; обязателен при запуске |
| `DOCCHECK_PORT` | Порт интерфейса на `127.0.0.1`, по умолчанию `8080` |
| `WORKER_POLL_SECONDS` | Интервал опроса очереди |
| `SYNTHETIC_DELAY_SECONDS` | Задержка синтетического задания |
| `DOCCHECK_DOCUMENT_PROCESSOR` | Точка входа отдельно подготовленного документного обработчика в форме `module:callable` |
| `DOCCHECK_DOCUMENT_WORKER_IMAGE` | Образ с установленным обработчиком для необязательного профиля `document-worker` |

Для смены порта измените `DOCCHECK_PORT` и повторите `docker compose up -d`.
Пароль базы используется при первичном создании тома: изменение `.env`
само по себе не меняет пароль в существующей базе. Переменная `DATABASE_URL`
из примера предназначена для запуска backend вне Compose; внутри Compose
адрес базы формируется из `DOCCHECK_DB_PASSWORD`.

Профиль `document-worker` требует отдельно подготовленного образа и
доступного обработчика. Штатный образ не содержит всех зависимостей v3.2;
одного указания `DOCCHECK_DOCUMENT_PROCESSOR` недостаточно для его запуска.
Сеть контейнера и доступ к локальной модели также нужно настроить и проверить.
[Подробности backend и профиля](backend/README.md#отдельный-документный-worker-в-compose)

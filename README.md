# DocCheck

Локальная сверка карточки фактических затрат (КФЗ) с первичными документами: извлечение, точные расчёты и доказательства расхождений.

Проект команды **«Буткемперы»**, хакатон МФТИ, трек 5.

## Текущий этап

Синтетический каркас связывает frontend, FastAPI, PostgreSQL и отдельный Python worker. В интерфейсе видно состояние API и прохождение задания через очередь, обработку и завершение. [Настройка БД, миграции и команды запуска](backend/README.md). Тестовый результат явно помечен. Загрузка документов, OCR и финансовая сверка относятся к следующим задачам; общий контракт результата ещё не зафиксирован.

Для подключения к backend доступен [Python-модуль реквизитов и Qwen-reader](backend/ml_module/README.md)
с тестами и синтетическим примером без весов. Он обрабатывает готовые наблюдения
и не заменяет полный конвейер финансовой сверки.

## Структура

```text
backend/             Python: API, worker, обработка и денежная логика
backend/tests/       Тесты backend и инструкции для них
frontend/            TypeScript: пользовательский интерфейс
frontend/tests/      Тесты frontend и инструкции для них
contracts/           Решения по общему контракту после согласования
docs/                Архитектура и правила разработки
data/                Локальные оригиналы, превью и результаты; вне Git
```

## Начало работы

```sh
git clone https://github.com/FeraFeraKA/doccheck.git
cd doccheck
```

```sh
git diff --check
```

Для приватного репозитория владелец выдаёт участникам доступ; каждый проверяет клонирование под своим аккаунтом. Успешное клонирование владельцем не подтверждает доступ остальных участников.

## Планируемый стек

Frontend: React, TypeScript, Vite, React Router, Zustand, Tailwind CSS и собственные компоненты; менеджер пакетов — pnpm. Подробности и статус настройки — в [frontend/README.md](frontend/README.md). Backend: Python/FastAPI, SQLAlchemy, Alembic, отдельный Python worker и PostgreSQL. Миграция создаёт схему синтетических заданий. По целевой архитектуре оригиналы хранятся локально, PostgreSQL хранит задания, метаданные и результаты. Redis и внешний LLM для MVP не требуются. Docker Compose остаётся отдельной задачей NRT-41.

# Общий контракт результата

Источник: JSON Schema 0.1 и synthetic_result.json в [документе Linear «Данные, контракт и приёмка»](https://linear.app/andreiakimov/document/dannye-kontrakt-i-priyomka-1c729510a76b).

## Статус импорта

Оригинальные JSON пока отсутствуют. При подготовке NRT-6 обе ссылки, включая повторное чтение документа, вернули HTML приложения Linear. HTML удалён; схема по текстовому описанию не реконструировалась.

После получения файлов поместить оригинальную схему в `contracts/check_result.schema.json`, синтетическую фикстуру — в `tests/fixtures/synthetic_result.json`. Проверить валидность JSON, соответствие схеме и `synthetic: true`. До этого нельзя заявлять валидацию контракта или соответствие моделей исходной схеме.

## Зафиксированные правила

- Python-модели (NRT-18) и TypeScript-типы используют один исходный контракт.
- Общие разделы: schema_version, run_id, synthetic, scope, versions, documents, evidence, rows, summary.
- Статусы показателей: verified / discrepancy / unverified.
- Деньги передаются строками с двумя знаками после точки, отсутствующие значения — null по правилам схемы.
- Вычисления выполняются в Python через Decimal или копейки.
- Состояния задания и HTTP-маршруты задаются отдельно в NRT-13.
- Смысл полноты, ссылки доказательств и арифметика требуют проверок сверх JSON Schema.

Это памятка по опубликованному описанию, а не альтернативная машинная схема. Изменения контракта согласуются с владельцем ядра.

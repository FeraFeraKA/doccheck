# Контракт результата сверки

Версия `doccheck-check-result/1`. Единственный источник машинного контракта —
[модели Pydantic](../backend/src/doccheck_backend/contracts/).
[Семантика полей](../docs/result-source-contract.md) согласована в NRT-85.
Схема [`check-result.v1.schema.json`](check-result.v1.schema.json)
генерируется из `CheckJob` и содержит `CheckResult` в `$defs`.
[`check-result.v1.synthetic.json`](check-result.v1.synthetic.json) показывает
обмен между обработчиком, API и UI с вымышленными документами и значениями.

## Воспроизведение

Из `backend/` в окружении проекта:

```sh
uv run --frozen python ../contracts/generate.py
uv run --frozen pytest tests/test_result_contract.py
```

Штатный прогон включает регрессии Draft 2020-12 с версией `jsonschema`
из `backend/uv.lock`.

Схема Draft 2020-12 описывает поля, значения статусов, денежные строки и
структуру адресов. Она требует слагаемые для наблюдаемой суммы, ссылки
для значения отчёта и причину для расхождения. Модели дополнительно
проверяют суммы, дельту, ссылки внутри задания, порядок координат,
диапазоны XLSX, полноту и связь статусов.
Для проверки JSON используйте `CheckJob.model_validate_json()` или
`CheckResult.model_validate_json()`. `fragment_id` для PDF/PNG означает ID
конкретного фрагмента в сохранённом извлечении. Адаптер проверяет доступность
фрагмента, роли доказательств и их соответствие выбранной области.

В версии 1 `calculation.operation: "sum"` задаёт суммирование допущенных
слагаемых. При полном покрытии `expected_value` равно проверенной сумме этих
слагаемых. При неизвестной операции или отсутствии слагаемых ожидаемое
значение остаётся `null`, включая случай заявленной полноты. Текст
`calculation.formula` предназначен для отображения, а `policy_id` фиксирует
версию правила допуска. Диапазон одной ячейки XLSX канонизируется при чтении
в её адрес, например `C6:C6` в `C6`.

Адреса PDF/PNG сопоставляются в пределах документа и страницы по ID
фрагмента, рамке или ячейке. Если у адреса есть только воспроизводимая
строка, она служит ключом. Модель сверяет нормализованный номер договора,
явно выходящий за область период и код статьи, когда он задан. Для
сопоставления назначения работ со статьёй адаптер записывает нормализованный
код и объясняет правило связи в `relation_reason`.

Чтения суммы по одному адресу должны совпадать по значению и единице,
включая чтения из реестра доказательств, отсутствующие в списке ссылок
слагаемого или строки. В одном документе на одной странице совпадение
точных адресов связывает чтения транзитивно. Например, наблюдение с рамкой
и идентификатором фрагмента связывает наблюдения только с рамкой и только
с этим идентификатором. Такая группа учитывается в расчёте один раз.
Номер строки относится к той же группе, если в ней найден один точный
фрагмент. Когда на строке есть несколько разных точных фрагментов,
для подтверждения значения нужен точный адрес, даже если чтения совпали.
При конфликте обработчик сохраняет чтения в `evidence`, добавляет причину
и оставляет зависимую строку `unverified`.
Конфликтующее слагаемое исключается из расчёта. При конфликте в отчёте
`reported_value` остаётся `null`.

Договор, период и статья подтверждаются в допущенной первичке. Чтения
одного реквизита по одному адресу должны быть согласованы. Совместимые
частичные даты вместе задают известные границы периода. Перед допуском
слагаемого сверяются явные границы из всех его ссылок. Если самое позднее
из известных начал позже самого раннего известного конца, слагаемое
остаётся кандидатом. Неизвестные границы сохраняются в наблюдениях.
Для реквизитов из отдельного допущенного источника `identity_refs` связывает
адресные доказательства `document_identity` с одним нормализованным
идентификатором в обоих документах. Для подтверждения связи чтения
реквизита по каждому адресу должны совпадать. Адаптер проверяет смысл
и уникальность этого идентификатора по применимому правилу. Реквизиты
самого отчёта служат для задания области сверки.

Полнота опирается на адресные доказательства с согласованными чтениями.
Если доказательство полноты неоднозначно, обработчик сохраняет причину,
подтверждённые слагаемые и их наблюдаемую сумму. Строка остаётся
`unverified` с `null` для ожидаемого значения и дельты. Конфликт,
который не затрагивает слагаемые или независимое основание полноты,
можно сохранить в реестре наблюдений.

Ошибки чтения получают ID внутри результата. Строка связывается с первичной
причиной через `root_issue_id`, а причина с ошибкой файла через
`file_error_refs`. Задание с сохранённым результатом и зафиксированным
техническим сбоем получает `completed_with_issues`.

Денежные строки в RUB содержат два десятичных знака. Синтетический пример
показывает две разные операции с одинаковой суммой, исключённую копию
ведомости, подтверждённое расхождение и непроверенную строку с отчётным нулём.
Для изменения смысла поля или статуса потребуется новая версия.

Синтетический HTTP-каркас использует свой временный ответ. Подключение общего
контракта к маршрутам, обработчику и UI относится к следующим задачам.
Предметная приёмка остаётся за владельцами.

## HTTP API v0

[OpenAPI](doccheck-api.v0.openapi.yaml) описывает создание задания, историю,
состояние, результат, источники и экспорт XLSX. Схемы результата и
доказательства подключены ссылками на
[JSON Schema версии 1](check-result.v1.schema.json).
Для создания задания достаточно КФЗ и первичных документов. Номер договора,
границы периода и адрес строки КФЗ совместимый старый клиент может передать
единым комплектом. Без этих полей область определяется в обработчике после
приёма пакета. Результат версии 1 сохраняет одну область для той же КФЗ.
Для разработки UI используйте [синтетический JSON](check-result.v1.synthetic.json).
Тело примера целиком соответствует `CheckJob`, его поле `result` соответствует
ответу `GET /api/v0/runs/{run_id}/findings`. В рабочем API фикстура недоступна.
Маршруты из OpenAPI описывают будущую реализацию NRT-96, NRT-97 и NRT-36.

Команда из CI для проверки OpenAPI и ссылок на схемы запускается из `backend/`.

```sh
uv run --frozen openapi-spec-validator ../contracts/doccheck-api.v0.openapi.yaml
```

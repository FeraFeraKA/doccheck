# Контракт результата сверки

Версия `doccheck-check-result/1`. Единственный источник машинного контракта —
[модели Pydantic](../backend/src/doccheck_backend/contracts/).
[Семантика полей](../docs/result-source-contract.md) согласована в NRT-85.
Схема [`check-result.v1.schema.json`](check-result.v1.schema.json)
генерируется из `CheckJob` и содержит `CheckResult` в `$defs`.
[`check-result.v1.synthetic.json`](check-result.v1.synthetic.json) показывает
обмен между обработчиком, API и UI с вымышленными документами и значениями.

## Воспроизведение

Из `backend/` в окружении проекта:

```sh
uv run --frozen python ../contracts/generate.py
uv run --frozen pytest tests/test_result_contract.py
```

Схема Draft 2020-12 описывает поля, значения статусов, денежные строки и
структуру адресов. Модели дополнительно проверяют суммы, дельту, ссылки внутри
задания, порядок координат, диапазоны XLSX, полноту и связь статусов.
Для проверки JSON используйте `CheckJob.model_validate_json()` или
`CheckResult.model_validate_json()`. `fragment_id` для PDF/PNG означает ID
конкретного фрагмента в сохранённом извлечении. Адаптер проверяет доступность
фрагмента, роли доказательств и их соответствие выбранной области.

В версии 1 `calculation.operation: "sum"` задаёт суммирование допущенных
слагаемых. При полном покрытии `expected_value` равно проверенной сумме этих
слагаемых. При неизвестной операции или отсутствии слагаемых ожидаемое
значение остаётся `null`, включая случай заявленной полноты. Текст
`calculation.formula` предназначен для отображения, а `policy_id` фиксирует
версию правила допуска. Диапазон одной ячейки XLSX канонизируется при чтении
в её адрес, например `C6:C6` в `C6`.

Адреса PDF/PNG сопоставляются в пределах документа и страницы по ID
фрагмента, рамке или ячейке. Если у адреса есть только воспроизводимая
строка, она служит ключом. Модель сверяет нормализованный номер договора,
явно выходящий за область период и код статьи, когда он задан. Для
сопоставления назначения работ со статьёй адаптер записывает нормализованный
код и объясняет правило связи в `relation_reason`.

Ошибки чтения получают ID внутри результата. Строка связывается с первичной
причиной через `root_issue_id`, а причина с ошибкой файла через
`file_error_refs`. Задание с сохранённым результатом и зафиксированным
техническим сбоем получает `completed_with_issues`.

Денежные строки в RUB содержат два десятичных знака. Синтетический пример
показывает две разные операции с одинаковой суммой, исключённую копию
ведомости, подтверждённое расхождение и непроверенную строку с отчётным нулём.
Для изменения смысла поля или статуса потребуется новая версия.

Синтетический HTTP-каркас использует свой временный ответ. Подключение общего
контракта к маршрутам, обработчику и UI относится к следующим задачам.
Предметная приёмка остаётся за владельцами.
